Two-Minute Guide

Add a compatible OpenAI API model locally

Use this file when a new OpenAI model follows request semantics RepoPrompt CE already understands, but the model is not yet compiled into the app.

Before You Start

Two conditions must both be true

  • Your configured provider’s GET /v1/models response contains the exact model ID.
  • The model works with the Responses API and only uses modes/efforts already accepted by the app.
This file does not grant API access. It only tells the app how to present a model your account can already see.

Step 1

Create the folder and file

In Terminal:

mkdir -p "$HOME/Library/Application Support/RepoPrompt CE/ModelCatalog"
open -e "$HOME/Library/Application Support/RepoPrompt CE/ModelCatalog/openai-model-metadata-v1.json"

The second command opens the file in TextEdit. If it does not exist, save it at that exact path.

Step 2

Paste a starter document

{
  "schema_version": 1,
  "models": [
    {
      "id": "gpt-future-example",
      "display_name": "GPT Future Example",
      "protocols": ["responses"],
      "reasoning": {
        "modes": ["standard", "pro"],
        "efforts": ["none", "low", "medium", "high", "xhigh"]
      },
      "streaming": true,
      "tokens": {
        "context_window_tokens": 200000,
        "max_output_tokens": 32000
      }
    }
  ]
}

Replace the example ID, label, capabilities, and token values with accurate provider documentation. The id must match /v1/models exactly, including punctuation and case.

Step 3

Use only accepted values

FieldCurrent accepted valuesNotes
protocolsresponses, chat_completionsUse responses for a selectable configured reasoning model.
modesstandard, proInclude only modes the model really supports.
effortsnone, minimal, low, medium, high, xhigh, maxGPT-5.6’s built-in picker shows every supported value except minimal; minimal remains accepted for metadata-backed models that support it.
streamingtrue or falseThis is required and persists with the selection.
tokensPositive integersOptional. If present, context_window_tokens is required.
Pro mode and reasoning effort are independent for GPT-5.6. The built-in picker therefore offers None, Low, Medium, High, XHigh, and Max under both Standard and Pro. Older standalone Pro model IDs had different restrictions.

Step 4

Validate the JSON

python3 -m json.tool \
  "$HOME/Library/Application Support/RepoPrompt CE/ModelCatalog/openai-model-metadata-v1.json" \
  > /dev/null && echo "JSON is valid"

Expected: JSON is valid. This checks JSON syntax; RepoPrompt CE still performs stricter schema validation when it loads the file.

Step 5

Reload and verify

  1. Restart RepoPrompt CE or reopen/refresh the configured OpenAI API provider.
  2. Open the model picker.
  3. Find the exact model ID.
  4. Select a supported mode and effort, save, and reopen Settings.
Success means the model appears and the selected mode/effort survives reopening Settings. Send a small non-sensitive prompt to verify your account can actually run it.

Adding More Models

Append another object inside models

{
  "schema_version": 1,
  "models": [
    { "id": "first-model",  "protocols": ["responses"], "reasoning": { "modes": ["standard"], "efforts": ["medium"] }, "streaming": true },
    { "id": "second-model", "protocols": ["responses"], "reasoning": { "modes": ["standard", "pro"], "efforts": ["low", "high"] }, "streaming": false }
  ]
}

Separate model objects with commas. Do not add a comma after the final object.

Troubleshooting

If the model does not appear

  1. Run the JSON validation command again.
  2. Confirm the file name is exactly openai-model-metadata-v1.json.
  3. Confirm the model ID appears in the configured provider’s /v1/models result.
  4. Remove unknown fields; the decoder intentionally uses a strict schema.
  5. Confirm protocols includes responses and reasoning is present.
  6. Restart the app after saving.
Never put API keys, headers, endpoints, request fragments, or secrets in this file. They are unsupported and may cause the document to be rejected.

Current Limitations

Know what metadata does not do

  • A new request field or reasoning mode still requires a code update.
  • The picker currently shows the raw model ID instead of display_name for metadata-backed models.
  • Token metadata is validated but does not automatically become the runtime request cap.
  • The file applies to the configured OpenAI-compatible endpoint, including a custom proxy. Treat each entry as your assertion that that endpoint supports the declared request fields; an inaccurate entry can cause an upstream request failure.
  • This file applies only to the OpenAI API-provider catalog, not Anthropic or CLI providers.

For provider facts, consult the OpenAI model catalog and the specific model’s documentation before adding an entry.
