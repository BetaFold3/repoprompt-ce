## 1. Goal and non-goals

**Goal.** (A) Replace the flat "existing branches" `NSMenu` and the prose confirmation sheet with one visual conversation-tree picker that the ⌘⇧T shortcut, the titlebar button, and the reply-footer icon all open — before the first branch exists — where the user selects the turn to branch from, previews it, and sees a compact structured safety footer. Disambiguate the branch and handoff icons and make the reply control icon-only. (B) Extend native branching to qualified local Claude-compatible native launch profiles (`claudeCode`, `claudeCodeGLM`, `kimiCode`, `customClaudeCompatible`) using a CE-native, SDK-shaped child-store transform plus the documented CLI resume reader. Preserve exact native context validation, one persisted CE session per branch, a source never opened for writing by branching, exact-session Oracle ownership, no fresh-start fallback for tree members, a single native publication attempt, and no filesystem/Git/workspace rollback. Exact resume also preserves an explicit residual: after a user frame may have entered the CLI pipe but before identity confirmation, delivery can be indeterminate (§3.5); CE never represents such a turn as admitted to the branch.

**Non-goals.** Remote/gateway, MCP-originated, child-agent, and worktree-bound sessions; ACP/OMP/Cursor and Pi providers; checkpoint backfill for pre-existing turns; edit-earlier-prompt; MCP branch command; filesystem snapshot or `--rewind-files`; cross-window occupancy; Oracle chat cloning; bundling Python, Node, Bun, or either Agent SDK in the app; the disproved CLI-fork flags or `/branch`; mutating a source Claude transcript; deleting a published Claude child; compaction support in v1; cloning subagent execution histories or source-owned resumable subagents.

## 3. Settled design (both lanes converged or resolved in §4; adopt)

### 3.1 Provider-neutral branch contracts (`Runtime/Branching/`)

- Keep the two provider ledgers separate (`CodexTurnCheckpointLedger` untouched; new `ClaudeTurnCheckpointLedger`); add a small neutral façade in `AgentBranchCheckpoint.swift`: hoisted `AgentTurnCheckpointStatus` / `AgentTurnSideEffect` (same case names, synthesized Codable, so Codex JSON is byte-identical; Codex keeps `typealias Status/SideEffect`), `AgentBranchNativeTurnRef` (`.codexTurn(id:)`, `.claudeEntry(lastEntryUUID:promptEntryUUID:)`), `AgentBranchCheckpoint {turnID, status, sideEffect?, nativeRef, recordedAt}`, and `AgentBranchCheckpointIndex {byTurnID, duplicateTurnIDs}` built by each ledger. `AgentBranchProviderSupport` remains a per-kind kill switch rather than enabling every `usesClaudeNativeRuntime` case by inference. `AgentBranchRuntimeCapability` becomes `.notApplicable`, `.unknown`, `.supported(evidence:)`, or `.unsupported(reason)`; evidence distinguishes release-qualified from locally probed readers, and typed reasons include `versionBelowFloor`, `versionDenylisted`, `unrecognizedLaunchProfile`, `executableIdentityUnavailable`, `probeStageFailed`, `probeTimedOut`, and `storeUnavailable`. The obsolete hidden-flag reason is removed.
- `AgentSessionBranchAvailability.available(AgentBranchCheckpoint)`; `Reason` gains `.runtimeCapabilityUnknown`, `.runtimeUnsupported(reason)`, `.unsupportedHistory(compaction|sidechain|ambiguousSegment)`, `.turnNotRetained`, `.treeEvidenceUnavailable`.
- `AgentSessionBranchGate` splits `staticUnavailableReason(session)` (provider support, remote, MCP-originated, child, worktree — used for UI visibility so controls do not flicker during runs) from the transient checks in `operationUnavailableReason`; `evaluate` adds the capability gate, native binding lookup, checkpoint lookup, and history eligibility.
- `CodexBranchOperationError` is renamed `AgentBranchOperationError` with `typealias CodexBranchOperationError = AgentBranchOperationError`, existing cases untouched, plus `.claude(ClaudeBranchFailure)`, `.nativeIndeterminate(provider:knownChildID:)`, `.childSavedButNotOpened(sessionID:)`. Native outcomes are typed (`notAttempted`, `indeterminate(knownChildID?)`, `validatedChild`); retry safety is never inferred from message text.
- `AgentBranchSafetySummary` (pure) absorbs `AgentReplyBranchPresentation`'s second initializer, `hasResolvedTranscriptTurn`, `canPresentConfirmation`, the `confirmation*` copy, and `impact(of:ledger:)` (input: selected index in `transcriptTurnIDs`, `AgentBranchCheckpointIndex`, Oracle count). `AgentReplyBranchPresentation` keeps `turnID`, `availability`, `isOperationInProgress`, `isAvailable`, `disabledHelpText`, `isEligibleBlock`.

### 3.2 Persistence, lineage, and index

- **One `branchOrigin` wire object.** In-memory `sourceCodexTurnID` becomes `sourceNativeTurnRef: String`, encoded under the legacy coding key `sourceCodexTurnID` (non-optional, so older builds decode a Claude branch unchanged and retain lineage on re-save), plus optional `sourceProviderKind: String?` (key `sourceProviderKind`, absent ⇒ Codex, diagnostic only). Runtime dispatch reads the session's native binding (`codexConversationID`/`codexTurnCheckpoints` vs `providerSessionID`/`claudeTurnCheckpoints`), never the origin's provider field; a binding/origin contradiction disables branch operations and never quarantines a readable transcript. Document the legacy key in a doc comment. Audit every `sourceCodexTurnID` consumer to confirm none feeds it into a Codex runtime call without a `.codexExec` binding guard (§4 A flip condition).
- `AgentSession.claudeTurnCheckpoints: ClaudeTurnCheckpointLedger?` under new additive key `claudeTurnCheckpoints`; **serialization version stays 7**. Older builds ignore and drop it on re-save (same documented degradation as `codexTurnCheckpoints`).
- Metadata index: add `branchSourceSessionID: UUID?` and `branchSourceTurnID: UUID?` to `AgentSessionMetadataRecord`, projected from `branchOrigin` for both providers; **bump `currentSchemaVersion` 6 → 7** so the existing equality-mismatch rebuild re-projects every record once (stub loads only). `AgentSessionBranchTree` gains `children(of:)` from `branchSourceSessionID ?? rootSessionID` and `lineageIncompleteIDs`; a record with a root but no source attaches under the root with a visible `Source path unavailable` marker (never asserted as a real parent); a deleted intermediate source renders a non-actionable `Deleted source path` placeholder. Topology validation rejects cycles, contradictory roots, and parents outside the tree. Phase 1 validation must time the rebuild on a large sessions folder (D's evidence request); if it blocks launch, revisit.
- `AgentTranscriptIO.branchPrefix` additionally prunes `providerTokenUsageByTurn` to retained turns (Claude stores per-turn usage there).

### 3.3 Claude checkpoint capture (`Runtime/Claude/ClaudeTurnCheckpointLedger.swift`)

```swift
struct ClaudeTurnCheckpointLedger: Codable, Equatable, Sendable {
    var threadID: String                       // Claude session_id
    var entries: [ClaudeTurnCheckpoint]
    var compactionMarkers: [ClaudeCompactionMarker]   // {afterTurnID, boundaryEntryUUID?, recordedAt}
    var historyLockout: ClaudeHistoryLockout?  // persisted; reset only on a genuinely different native binding
}
struct ClaudeTurnCheckpoint: Codable, Equatable, Sendable {
    let turnID: UUID                 // CE user-turn id
    var promptEntryUUID: String      // caller-supplied accepted submission uuid; required for eligibility
    var lastEntryUUID: String?       // final main-chain assistant payload uuid before the successful `result`
    var status: AgentTurnCheckpointStatus
    var sideEffect: AgentTurnSideEffect?
    let recordedAt: Date
}
```

- Same operation vocabulary as the Codex ledger (`bind(to:)`, `matching(threadID:)`, `record`, `transition`, `prune`, `pruneForPersistence`, `checkpointIndex()`); mirrored on `TabSession`; synced through the Claude analog of `restoreCodexMetadata`/`applyCodexPersistence`; pruned on save.
- Recording in `ClaudeAgentModeCoordinator`: associate the caller-reserved prompt UUID only after the submission is accepted; bind on the first matching event carrying `session_id`; update `lastEntryUUID` only from main-chain assistant payloads; fold issued tool-use blocks into the side-effect summary; append compaction and delegation evidence; and seal on the original `result` payload, which remains the authoritative turn boundary. Only an uninterrupted successful result with the prompt UUID and a final assistant UUID becomes a branchable checkpoint. Failed, cancelled, partial, duplicate, contradictory, or incomplete evidence remains persisted for history classification but is never a selectable anchor. No per-turn disk reads.
- Package changes: `ClaudeProviderStreamResult` gains `entryUUID`, `parentToolUseID`, and a typed `compactBoundary` sub-DTO; `ClaudeSDKNDJSONTranslator` extracts them (existing consumers unchanged); the runtime bridge maps them onto `AIStreamResult` additively. The codec's user-message encoder accepts an optional caller-supplied `uuid` (§4 E).
- Side-effect classification (`ClaudeCompatibleToolSideEffectClassifier`, pure, in the package, with an injected RepoPrompt-MCP policy closure; issuance-based — denied or errored edits still count): `Edit`/`Write`/`MultiEdit`/`NotebookEdit` → `modified([file_path | notebook_path])`, lexically normalized against the runtime cwd (no symlink resolution, paths outside the workspace preserved); `Read`/`Grep`/`Glob`/`LS`/`WebFetch`/`WebSearch`/`TodoWrite`/`AskUserQuestion`/`ExitPlanMode` → read-only; `Bash` and any unlisted tool → `unknown`; `Task`/`Agent` → classified from nested tool_use events observed via `parent_tool_use_id`, `unknown` if none; `mcp__*` → `unknown` unless RepoPrompt's canonical tool metadata classifies it (reuse the Codex path's table if one exists; never create two). Aggregation keeps the existing rule: any unknown ⇒ unknown; else union of modified paths; else read-only.
- History eligibility is evaluated per candidate from the retained prefix. The inclusive anchor is the successfully completed CE turn's verified final main-chain assistant entry; prompt, tool-result, sidechain, progress, metadata, failed, cancelled, and partial records are never anchors. A retained prefix must be linear, closed over tool-use/tool-result pairs, attributable to caller-supplied prompt UUIDs, free of unknown conversation-bearing records and dangling/external references, and end exactly at the checkpoint anchor. Recognized non-prompt progress records may be retained only when the reference transform and request-capture probe establish their qualified contraction; unattributed prompt-shaped records reject that candidate.
- Any observed compaction/content-replacement shape causes a persisted whole-binding v1 lockout; G-COMPACTION is a later policy-extension gate and does not block plain histories. Sidechains in the omitted suffix do not disqualify an earlier anchor. A retained completed delegation is eligible only after G-SIDECHAIN proves that the parent-visible result is sufficient while sidechain transcripts and source-owned resumable agents remain excluded; incomplete, ambiguous, externally referenced, or active delegation rejects that candidate. A failed/unanswered suffix after the selected anchor may be omitted. An earlier failed turn followed by a distinct successful retry is retained only for shapes qualified by G-FAILED; retries always use a new prompt UUID and neither fork recovery nor pending-send recovery automatically resubmits.

### 3.4 Claude fork transform, publication, recovery, and qualification

- **Production materializer.** Implement `ClaudeSessionStoreForkTransform` as pure Swift in `RepoPromptClaudeCompatibleProvider`. Input is a strictly validated immutable source snapshot, inclusive final-assistant anchor, CE-preassigned native child UUID, frozen source→child UUID mapping, timestamp, and title; output is immutable child bytes plus the complete mapping. It performs no filesystem access, process launch, credential access, or app persistence. Python `claude-agent-sdk` 0.2.152 is the pinned development oracle for accepted transformations; TypeScript 0.3.266 is optional triangulation only. The accepted domain is intentionally narrower than the SDK: malformed, unknown, ambiguous, non-linear, compacted, incomplete, or unsupported histories fail before publication. `writerFormatVersion` changes only through new fixtures and qualification evidence.
- **Ownership boundary.** Package code owns pure JSONL parsing, transformation, provenance verification, history policy, and capability rules. Core `ClaudeNativeSessionStore` owns bounded discovery, immutable reads, hashing, private staging, exclusive new-child publication, and verification. Feature code owns `ClaudeBranchOperationJournal`, the CE transaction, recovery state, and UI. `NativeAgentRuntimeControlling` and the interactive Claude controller gain no fork API. No Python/Node/Bun/SDK artifact ships in the app.
- **Identity and journal.** Before any native publication, allocate and durably record an operation UUID, CE child-session UUID, native child UUID, source CE/native identities, source path/file identity/raw SHA-256, inclusive anchor and prompt UUID, retained source manifest, frozen UUID mapping, pending CE child snapshot identity, expected artifact byte count/SHA-256, and writer/verifier/history-policy versions. Journal schema 1 states are `prepared → staged → publishArmed → published → validated → committed`, with terminal `aborted` and `indeterminate`. Correlation titles are display metadata only and are never recovery authority.
- **Single publication attempt.** Acquire the branch operation and app-wide native-binding lease; create and independently verify a non-discoverable staging file on the destination filesystem; revalidate the source, operation pin, and safety summary; durably persist `publishArmed`; then issue exactly one no-overwrite publication using `renameatx_np(..., RENAME_EXCL)`. Unsupported filesystem semantics fail qualification; never degrade to an existence-check plus overwriting rename or copy. The native attempt boundary is the armed exclusive publication, not transform construction. After that boundary, timeout, cancellation, crash, collision, or uncertain return never causes another publication or a new child ID.
- **Recovery and cleanup.** Reconciliation may repeat reads, verification, and the idempotent CE child save, but never the transform's publication. A verified exact destination with the recorded bytes and provenance is adopted and committed; a matching CE child means commit already completed. Private unpublished staging owned by the settled operation may be removed. A published child—including empty, partial, changed, foreign, or otherwise unverified content—is preserved and reported, never repaired, overwritten, or automatically deleted. Index/activation failure after CE save uses **Open created branch**, not another fork. The CE commit point remains the ordinary child-session atomic save.
- **Source quiescence.** The lease key is canonical config/store root plus native session ID and is consulted by every CE startup/send path. Stop and drain the idle source controller, settle pending events, reject active turns/approvals/background tasks or another CE owner, flush CE state, and obtain two matching source reads (file identity, length, raw SHA-256) separated by 250 ms within a five-second settlement bound. Recheck immediately before publication, after publication, and before CE commit. CE locks are advisory and do not bind an external Claude process; any append, truncation, replacement, or byte change in the guarded interval prevents CE commit and leaves a published child indeterminate until the journal proves safe verification. CE never restores or truncates the source.
- **Child verification and ledger remap.** Parse the complete published child and use each entry's immediate-source `forkedFrom` data to build a bijection from every retained source conversation UUID to the child UUID. Require the exact retained order and payloads; reminted UUIDs; mapped parent links; the expected child `sessionId`; no extra conversation entry; only qualified metadata/progress transformations; and an exact title record if emitted. Remap every retained checkpoint's prompt and final-assistant UUID, rebind the ledger thread ID, preserve CE turn IDs/status/side effects/token accounting, and keep lineage anchored to the immediate source. Structural/text similarity without provenance is insufficient.
- **Capability.** Creation requires CLI version `>= 2.1.266`, no static denylist entry, a recognizable resolved executable and launch-profile class, a passing per-installation behavioral probe, and per-operation history validation. Cache identity includes the resolved executable content digest and reported version, architecture, config/store identity, launch-profile class, and writer/verifier/history-policy/probe-schema versions; path/size/mtime are invalidation hints only. Recheck executable identity at launch. Opaque wrappers and unknown launch-affecting settings remain unavailable.
- **Strong offline probe.** In an isolated synthetic store, a loopback-only canned model endpoint captures the CLI's actual request. The probe must prove source authoring/discovery, Swift child creation, inclusive retained request order and tool relationships, omitted suffix absence, exact child identity, one prompt UUID, unchanged inherited prefix and source, reopen/leaf chaining, missing-target refusal with no file and no model request, and staging invisibility. It uses no live credentials, user hooks, RepoPrompt MCP, or external model service and must establish external-egress denial; if this cannot be implemented safely for a launch profile, that profile remains unavailable. A handshake-only probe is not a fallback. If request capture is infeasible on the shipped build, v1 falls back to the release-qualified `2.1.266` reader allowlist plus G0/G-SWIFT-READER rather than weakening the probe.

### 3.5 Exact resume and pending submission for Claude tree members

- Resolve `AgentNativeResumePolicy { exactOrFail, allowFreshFallback }` before consuming the next prompt. A branch child, a root known to have branches, unavailable tree evidence, or an unresolved native operation requires `exactOrFail`. All five current fresh-start fallbacks are disabled: no replacement controller, handoff injection, `--continue`, new session ID, ledger rebinding, or adoption of unexpected output. A live process may be reused only when already proven bound to the exact stored ID.
- For a new controller, preflight the current native file and recorded store binding, reader capability, ownership, and controller generation without changing the transcript or composer. Validate the original fork artifact as a prefix, not the entire file, because legitimate continuations append. Persist `ClaudeResumeSubmissionJournal` schema 1 with attempt/session/turn IDs, caller-reserved prompt UUID, expected native ID, controller generation, prepared message and attachment references, draft revision, and states `prepared → writeArmed → identityConfirmed → settled`, plus `notSent` and `indeterminate`.
- Launch only documented `--resume <exact-native-id>`. If the initialize acknowledgment carries an ID, it must already match. Persist `writeArmed` before writing the user frame exactly once. Until matching `system/init`, keep the turn pending outside the committed transcript and keep permission, tool, MCP, and Oracle dispatch closed. Matching identity admits the turn once, publishes the binding, and clears the composer only when its revision still matches. Unexpected pre-init output, mismatched or contradictory identity, stale-generation events, and exit before confirmation terminate the run and never publish output into the branch.
- Failure before a frame write is `notSent` and preserves the draft. After bytes may have entered the pipe—including a partial write—delivery is `indeterminate`: preserve the durable attempt and draft, never auto-resend, and say `The message may have been received, but the conversation could not be verified. Your draft is preserved.` If identity was confirmed and execution then fails, preserve an attempted/failed turn under that session. Disk reconciliation may establish that the UUID persisted in the requested session, but cannot prove the backend did not receive or act on it.
- This is the settled exact-resume contract: CE validates the target before sending, invokes only its exact ID, never binds or displays another session as the branch, and never fresh-starts. It does **not** promise zero remote delivery after the write boundary because CLI 2.1.266 exposes no pre-frame `system/init`. G-RESUME must qualify missing-target refusal, the pending state machine, identity mismatch, early exit, crash, draft revision races, and the disclosed one-prompt residual before enablement.

### 3.6 View-model transaction (`AgentModeViewModel`)

`branchFromTurn` becomes shared prologue → provider fork step → shared epilogue, without changing the Codex fork body beyond mechanical extraction. Prologue: selection-pin validation, `beginBranchOperation`, draft/attachment preservation, `flushSaveThrowing`, and refreshed confirmation if quiescence changes retained counts or impact. Provider step: existing `performCodexBranchFork`, or Claude `capability re-check → acquire binding lease → stop/drain source controller → stable source manifest → journal prepared/staged/publishArmed → one exclusive publication → child/source verification → checkpoint remap`. Both return `AgentNativeForkResult {nativeChild: .codex(threadID, rolloutPath?) | .claude(sessionID, storeURL, operationID, artifact), childLedger}` only after validation. Epilogue uses `AgentSessionBranchSnapshotBuilder`, persists the preallocated CE child idempotently, then restores/activates it. `BranchOperationPin` carries `AgentNativeBranchIdentity`; revalidate it after every suspension. Reconciliation calls the same pure commit function as the live path and never republishes. The existing path-switch operation remains separate and sends nothing.

### 3.7 Unified conversation tree picker

- One SwiftUI sheet `AgentConversationTreePicker` (resizable, ~840×560, min 720×480), owned by `AgentModeView` through `AgentConversationTreePickerState` (replaces `AgentReplyBranchConfirmationState`); it replaces both `AgentConversationBranchMenuPresenter` (deleted) and `AgentReplyBranchConfirmationSheet` (deleted). The VM publishes `conversationTreePresentationRequest {id, tabID, initialSelection}`; `AgentChatTitleClusterView` receives a `presentConversationTree` closure instead of menu snapshot/actions; the gate becomes `AgentConversationTreeRequestGate.shouldAccept(requestWindowID:currentWindowID:hasActiveAgentTab:)`; `shouldPresent` is deleted; presentation is idempotent (repeated requests focus the open picker). `.showAgentConversationBranches`, the shortcut preference, and `GlobalKeyboardShortcutsCoordinator` stay unchanged.

### 3.9 Error handling and edge cases

| Situation | Behavior |
|---|---|
| Tree index unavailable | Picker `.failed`; current path from memory; switching disabled; branching allowed only with independently valid native evidence; exact resume still required. |
| Inactive path load fails | Row-level error; other paths unaffected; read-only **Refresh** retries reads only. |
| Zero completed turns | `No completed turns yet.`; Branch disabled. |
| Selection pin stale or quiescence changed counts/impact | Footer refreshes and shows the stale copy; requires a new explicit activation before `publishArmed`. |
| Capability unknown | Turns show the checking state; one coalesced probe publishes only to the still-current capability identity. |
| Unsupported history/profile/version | Disable that candidate with the typed reason; no transform or publication. |
| Failure before `publishArmed` | `Claude could not prepare the branch. Nothing was published.`; private staging may be cleaned after verified ownership. |
| Exclusive publication collision | Preserve the destination; report collision; no retry and no CE child save. |
| Published child verifies and CE save is missing | Offer **Recover created branch**; verification and the same CE save may repeat, publication may not. |
| Published child is empty, partial, changed, foreign, or source stability is unprovable | `Branching left an unverified Claude session ({id}). The branch was not saved.` Preserve every published file. |
| Child saved, activation fails | `Branch created; could not open it` + **Open created branch**. |
| Resume fails before frame write | `This conversation could not be reopened. Your message was not sent.` Preserve the draft. |
| Frame may have been written before identity confirmation | `The message may have been received, but the conversation could not be verified. Your draft is preserved.` No automatic resend. |
| Identity confirmed, execution later fails | Preserve the attempted/failed turn under the confirmed native session. |
| Older build opens a Claude branch | Decodes lineage; re-save may drop Claude checkpoints/provider kind; continuing Claude trees on an older build is unsupported. |
| Unexpected runtime session ID | Terminate and reject; never rebind the ledger or display that output as the branch. |

**E — resolved by Phase 0: prompt UUID required.**

- *Position 1 (required).* Prefix equality proves that the child matches a native cut, not that the cut represents the selected CE turn; only a verified prompt UUID (caller-supplied stdin `uuid`, or the `--replay-user-messages` echo, correlated by UUID and never by text) ties the native chain to CE's submitted input. Turns without one are unavailable. Would accept "optional" only if the spike shows another explicit submission-to-chain identity (e.g., a correlated request ID) gives equivalent turn-boundary evidence across all qualified history shapes.
- *Position 2 (optional).* The CLI anchors truncation on the kept turn's last entry, so stream order is not needed to segment the chain: branch preflight walks the main chain from disk, splits it at prompt-shaped user entries, requires exactly one segment per CE turn, takes each segment's last entry as the anchor, and cross-checks the streamed assistant uuid; mandatory stdin-uuid/replay plumbing buys hardening, not correctness. Would flip to "required" if S3/S6 show routine turns persist main-chain user-role entries CE cannot classify (injected reminders, absorbed messages), making segment counts diverge from CE turns.
- *Recommendation and Phase 0 outcome.* Treat Position 1 as the default because its flip condition is unlikely while Position 2's is plausible: Claude Code is known to persist non-prompt user-role main-chain entries (tool results, injected system-reminder text), so "prompt-shaped" segmentation is fragile. S3 proved that both standard and replay-enabled submissions persist the caller-supplied stdin `uuid`; replay additionally echoes it. Therefore future Claude checkpoint work must require the caller-supplied UUID without enabling `--replay-user-messages`. Position 2's segment cross-check remains an additional fail-closed validation.

## 6. Risks and limitations

- CE deliberately owns a narrow versioned writer for Claude's non-public local JSONL format. Official SDK goldens, strict accepted-history rules, provenance-based verification, per-executable semantic probing, a denylist, and live reader gates reduce but do not eliminate upstream drift. Unknown input or reader behavior fails closed.
- Native publication and CE session persistence are separate commit points. The journal makes verified adoption deterministic but does not make the pair atomic; published children are never automatically deleted, so a crash or external race may leave a reported orphan.
- The source lease coordinates CE windows/processes only. Unrelated Claude processes can still append; repeated hashes detect observed races but cannot freeze external writers or prove when an append occurred after a crash.
- The pending-send exact-resume protocol cannot retract a prompt after bytes enter the CLI pipe. A failed identity confirmation may leave one delivery indeterminate. The attempt remains durable, tools/Oracle/output are not admitted, the draft is preserved, and no automatic resend occurs.
- The loopback request-capture probe may require networking entitlement or isolation work in the shipped app. G-PROBE inventories the actual bundle/entitlements and either proves safe request inspection or activates the explicit 2.1.266 allowlist contingency; it never weakens to ID-only probing.
- Older builds may preserve lineage while dropping Claude checkpoints/provider kind on re-save; continuing Claude trees on an older build is unsupported. Rollback disables creation without removing journals, lineage, or exact-resume safety.
- Compaction remains unsupported in v1. Sidechain and failed-history support is deliberately narrower than arbitrary Claude histories and expands only by versioned policy gates.
- Index schema 7's one-time stub rebuild remains a previously recorded follow-up; this amendment does not reopen that implementation. The Phase 2 visible smoke is complete as recorded in §5.

## 7. Explicit remaining qualification work

1. **G0 is the next blocking action for production writer work.** It must turn the partial Python-writer/CLI-reader evidence into a successful retained-context continuation; no design inference closes it.
2. **G-PROBE settles shipped loopback feasibility.** Inventory entitlements and launch isolation, implement request inspection with external egress denied, and record the exact executable/profile identity. If unavailable, the documented exact-2.1.266 allowlist contingency applies.

## 8. Maintainer-guidance check

- **User impact and invariant:** branch creation is prompt-free and eagerly durable; the source is never opened for writing; every retained entry is provenance-verified; tree members never fresh-start. Resume failures after the write boundary honestly expose delivery uncertainty rather than claiming rollback.
- **Root-cause confidence:** direct runs on 2.1.258 and 2.1.266 disprove the CLI fork materializer; independent Python and TypeScript SDK qualifications establish the eager transform; Python-child/CLI-reader identity and persistence are proven, with successful semantic completion explicitly pending G0.

- **State safety:** the only Claude-store write is exclusive creation of a new child path from independently verified staged bytes. Source/unrelated files are never mutated, published children are never deleted, and recovery never republishes or resends.
- **Scale and observability:** bounded off-main reads and record limits, one capability probe per strong identity, typed stages/reasons, app-wide lease, explicit journal state, and visible checking/indeterminate/recovery states.
- **Recommended scope:** Phase 3A may start now. G0 precedes production writer work; Phase 3B and 4a remain dark; Phase 4b/4c are explicit atomic enablement boundaries. If a hard gate fails, keep shipped Codex/picker behavior and Claude capture evidence without enabling creation.
- **Validation boundary:** provider tests for pure transform/policy, focused root tests for persistence/runtime, deterministic failure injection, full coordinated regressions, context/guardrail checks, approved network qualification, and signed/quarantined app verification before enablement.

After the initial timeout the harness closed stdin and observed the process exit during bounded EOF grace. Because that live report predates all-location child discovery, it does not prove global absence; it does prove that Claude CLI 2.1.258 did not satisfy the qualification contract under the tested observation path. The CLI-argv materializer is retired; the result blocks that path, not Phase 3A or the replacement Phase 3B design.
- **S1:** supported as historical parser evidence. The hidden `--resume-session-at` flag was recognized and, without `--resume`, exited nonzero with `Error: --resume-session-at requires --resume`; this does not qualify materialization, and the argv path is retired.
- **S2:** the source bytes remained unchanged, but child-prefix equality, UUID preservation policy, child `sessionId`, and `system/init` identity were inconclusive because no child materialized. Strict chain checks reject an empty or truncated child.
- **S3:** supported. Standard and replay-enabled submissions both persisted the caller-supplied stdin UUID in the empirically discovered store; replay additionally echoed it and the streamed user UUID matched disk. This resolves §4 E in favor of requiring the caller-supplied UUID without replay.
- **S4:** inconclusive. The valid `--resume-session-at <retained-anchor>` plus `--resume-drops-turn <dropped-prompt>` pair ran, but it mutated the isolated source store and exited nonzero without a classifiable non-JSON error; the harness restored the fixture. `--resume-drops-turn` remains excluded from v1.
- **S5–S6:** compaction, sidechain, and retained non-prompt-user ancestry remain inconclusive because S0 failed. The S6 fixture places the reminder in retained parent ancestry and derives expected membership by walking `parentUuid` links.
- **S7:** a bogus anchor failed without a child and reported `No message found with message.uuid of: <uuid>`; a prompt-entry/mid-turn anchor accepted initialization but produced no child before timeout and EOF grace.
- **S8:** source stores were empirically found for spaces/Unicode and symlink cwd shapes, but no child materialized, so the fork-location result remains inconclusive.
- **S9:** the live report classified this as supported because a missing source failed fast and produced the recognized redacted error `No conversation found with session ID: <uuid>`. That report predates separation of exact-name physical candidates from cwd qualification, so the no-child portion is treated as inconclusive until a future approved run; the current harness requires positively confirmed zero candidates.
- **S10:** observational and inconclusive. The harness terminated the process group only after the initialize control response and found no child bytes afterward; this is not a deletion guarantee.
- **S11:** the prompt-free start fired a configured `SessionStart` hook and returned the matching initialize control response, with no prompt, RepoPrompt MCP, assistant event, or model/tool-request evidence. Hook firing is a confirmed limitation.

The production branching/runtime path remains unchanged and no Claude feature gate was enabled.
