## 1. Goal and non-goals

**Goal.** (A) Replace the flat "existing branches" `NSMenu` and the prose confirmation sheet with one visual conversation-tree picker that the ⌘⇧T shortcut, the titlebar button, and the reply-footer icon all open — before the first branch exists — where the user selects the turn to branch from, previews it, and sees a compact structured safety footer. Disambiguate the branch and handoff icons and make the reply control icon-only. (B) Extend native branching to the Claude-compatible native provider family (`claudeCode`, `claudeCodeGLM`, `kimiCode`, `customClaudeCompatible`) using the Claude CLI's session-fork primitive, while preserving every v1 invariant: exact native context restore, one persisted session per branch, root never rewritten by branching, exact resume with no fresh-start fallback for tree members, exact-session Oracle ownership, one fork attempt with ambiguous outcomes never retried, and no filesystem/Git/workspace rollback.

**Non-goals.** Remote/gateway, MCP-originated, child-agent, and worktree-bound sessions; ACP/OMP/Cursor and Pi providers; checkpoint backfill for pre-existing turns; edit-earlier-prompt; MCP branch command; durable fork journal; filesystem snapshot or `--rewind-files`; cross-window occupancy; Oracle chat cloning; Claude compaction/subagent *history shapes* beyond what the Phase 0 spike proves (§3.4).

## 3. Settled design (both lanes converged or resolved in §4; adopt)

### 3.1 Provider-neutral branch contracts (`Runtime/Branching/`)

- Keep the two provider ledgers separate (`CodexTurnCheckpointLedger` untouched; new `ClaudeTurnCheckpointLedger`); add a small neutral façade in `AgentBranchCheckpoint.swift`: hoisted `AgentTurnCheckpointStatus` / `AgentTurnSideEffect` (same case names, synthesized Codable, so Codex JSON is byte-identical; Codex keeps `typealias Status/SideEffect`), `AgentBranchNativeTurnRef` (`.codexTurn(id:)`, `.claudeEntry(lastEntryUUID:promptEntryUUID:)`), `AgentBranchCheckpoint {turnID, status, sideEffect?, nativeRef, recordedAt}`, `AgentBranchCheckpointIndex {byTurnID, duplicateTurnIDs}` built by each ledger, `AgentBranchProviderSupport.isSupported(kind)` (`.codexExec` or `usesClaudeNativeRuntime`) and `nativeBinding(for:)`, and `AgentBranchRuntimeCapability` (`.notApplicable`, `.unknown`, `.supported(version:)`, `.unsupported(reason)` with `versionBelowFloor`, `flagMissing`, `probeFailed`, `probeTimedOut`).
- `AgentSessionBranchAvailability.available(AgentBranchCheckpoint)`; `Reason` gains `.runtimeCapabilityUnknown`, `.runtimeUnsupported(reason)`, `.unsupportedHistory(compaction|sidechain|ambiguousSegment)`, `.turnNotRetained`, `.treeEvidenceUnavailable`.
- `AgentSessionBranchGate` splits `staticUnavailableReason(session)` (provider support, remote, MCP-originated, child, worktree — used for UI visibility so controls do not flicker during runs) from the transient checks in `operationUnavailableReason`; `evaluate` adds the capability gate, native binding lookup, checkpoint lookup, and history eligibility.
- `CodexBranchOperationError` is renamed `AgentBranchOperationError` with `typealias CodexBranchOperationError = AgentBranchOperationError`, existing cases untouched, plus `.claude(ClaudeBranchFailure)`, `.nativeIndeterminate(provider:knownChildID:)`, `.childSavedButNotOpened(sessionID:)`. Native outcomes are typed (`notAttempted`, `indeterminate(knownChildID?)`, `validatedChild`); retry safety is never inferred from message text.
- `AgentBranchSafetySummary` (pure) absorbs `AgentReplyBranchPresentation`'s second initializer, `hasResolvedTranscriptTurn`, `canPresentConfirmation`, the `confirmation*` copy, and `impact(of:ledger:)` (input: selected index in `transcriptTurnIDs`, `AgentBranchCheckpointIndex`, Oracle count). `AgentReplyBranchPresentation` keeps `turnID`, `availability`, `isOperationInProgress`, `isAvailable`, `disabledHelpText`, `isEligibleBlock`.

### 3.2 Persistence, lineage, and index

- **One `branchOrigin` wire object.** In-memory `sourceCodexTurnID` becomes `sourceNativeTurnRef: String`, encoded under the legacy coding key `sourceCodexTurnID` (non-optional, so older builds decode a Claude branch unchanged and retain lineage on re-save), plus optional `sourceProviderKind: String?` (key `sourceProviderKind`, absent ⇒ Codex, diagnostic only). Runtime dispatch reads the session's native binding (`codexConversationID`/`codexTurnCheckpoints` vs `providerSessionID`/`claudeTurnCheckpoints`), never the origin's provider field; a binding/origin contradiction disables branch operations and never quarantines a readable transcript. Document the legacy key in a doc comment. Audit every `sourceCodexTurnID` consumer to confirm none feeds it into a Codex runtime call without a `.codexExec` binding guard (§4 A flip condition).
- `AgentSession.claudeTurnCheckpoints: ClaudeTurnCheckpointLedger?` under new additive key `claudeTurnCheckpoints`; **serialization version stays 7**. Older builds ignore and drop it on re-save (same documented degradation as `codexTurnCheckpoints`).
- Metadata index: add `branchSourceSessionID: UUID?` and `branchSourceTurnID: UUID?` to `AgentSessionMetadataRecord`, projected from `branchOrigin` for both providers; **bump `currentSchemaVersion` 6 → 7** so the existing equality-mismatch rebuild re-projects every record once (stub loads only). `AgentSessionBranchTree` gains `children(of:)` from `branchSourceSessionID ?? rootSessionID` and `lineageIncompleteIDs`; a record with a root but no source attaches under the root with a visible `Source path unavailable` marker (never asserted as a real parent); a deleted intermediate source renders a non-actionable `Deleted source path` placeholder. Topology validation rejects cycles, contradictory roots, and parents outside the tree. Phase 1 validation must time the rebuild on a large sessions folder (D's evidence request); if it blocks launch, revisit.
- `AgentTranscriptIO.branchPrefix` additionally prunes `providerTokenUsageByTurn` to retained turns (Claude stores per-turn usage there).

### 3.3 Claude checkpoint capture (`Runtime/Claude/ClaudeTurnCheckpointLedger.swift`)

```swift
struct ClaudeTurnCheckpointLedger: Codable, Equatable, Sendable {
    var threadID: String                       // Claude session_id
    var entries: [ClaudeTurnCheckpoint]
    var compactionMarkers: [ClaudeCompactionMarker]   // {afterTurnID, boundaryEntryUUID?, recordedAt}
    var historyLockout: ClaudeHistoryLockout?  // persisted; reset only on a genuinely different native binding
}
struct ClaudeTurnCheckpoint: Codable, Equatable, Sendable {
    let turnID: UUID                 // CE user-turn id
    var promptEntryUUID: String?     // see §4 E (open)
    var lastEntryUUID: String?       // last main-chain assistant payload uuid (parent_tool_use_id == nil) before `result`
    var status: AgentTurnCheckpointStatus
    var sideEffect: AgentTurnSideEffect?
    let recordedAt: Date
}
```

- Same operation vocabulary as the Codex ledger (`bind(to:)`, `matching(threadID:)`, `record`, `transition`, `prune`, `pruneForPersistence`, `checkpointIndex()`); mirrored on `TabSession`; synced through the Claude analog of `restoreCodexMetadata`/`applyCodexPersistence`; pruned on save.
- Recording in `ClaudeAgentModeCoordinator`: bind on the first event carrying `session_id`; `record` when the turn's submission is accepted; update `lastEntryUUID` on each main-chain assistant payload; fold tool_use blocks into the side effect (main and sidechain); append a compaction marker on `compact_boundary`; **seal on the original `result` payload** (already the controller's authoritative turn boundary) — `completed` only for uninterrupted success, otherwise `cancelled`/`failed` through the existing terminal-settlement path; a turn with no observed `lastEntryUUID` seals `failed`. No per-turn disk reads (§4 E, converged part).
- Package changes: `ClaudeProviderStreamResult` gains `entryUUID`, `parentToolUseID`, and a typed `compactBoundary` sub-DTO; `ClaudeSDKNDJSONTranslator` extracts them (existing consumers unchanged); the runtime bridge maps them onto `AIStreamResult` additively. The codec's user-message encoder accepts an optional caller-supplied `uuid` (§4 E).
- Side-effect classification (`ClaudeCompatibleToolSideEffectClassifier`, pure, in the package, with an injected RepoPrompt-MCP policy closure; issuance-based — denied or errored edits still count): `Edit`/`Write`/`MultiEdit`/`NotebookEdit` → `modified([file_path | notebook_path])`, lexically normalized against the runtime cwd (no symlink resolution, paths outside the workspace preserved); `Read`/`Grep`/`Glob`/`LS`/`WebFetch`/`WebSearch`/`TodoWrite`/`AskUserQuestion`/`ExitPlanMode` → read-only; `Bash` and any unlisted tool → `unknown`; `Task`/`Agent` → classified from nested tool_use events observed via `parent_tool_use_id`, `unknown` if none; `mcp__*` → `unknown` unless RepoPrompt's canonical tool metadata classifies it (reuse the Codex path's table if one exists; never create two). Aggregation keeps the existing rule: any unknown ⇒ unknown; else union of modified paths; else read-only.
- History eligibility (per candidate, not per conversation): turns at or before an observed compaction marker are `.beforeCompaction`; turns after remain candidates; sidechain entries (`isSidechain`/`parent_tool_use_id`) can never be anchors; a turn whose disk segment contains more than one main-chain prompt-shaped user entry (absorbed/queued prompts) is `.unsupportedHistory(ambiguousSegment)`. If spike S5 shows a post-boundary fork's child main chain differs from the source sub-chain, compaction becomes a persisted whole-conversation `historyLockout` for v1.

### 3.4 Claude fork primitive, verification, and qualification

- Scope: all four `usesClaudeNativeRuntime` kinds, gated per resolved executable + launch profile by the qualification below; live smoke on standard Claude Code only.
- **Eager, prompt-free materialization at branch time** with a CE-preassigned child UUID:

```text
<resolved-claude> -p --verbose --output-format stream-json --input-format stream-json
  --permission-prompt-tool stdio [--append-system-prompt "Running within RepoPrompt CE." (GLM)]
  [existing permission-mode / --disallowedTools flags of the source profile]
  --resume <sourceSessionID> --fork-session --session-id <childUUID>
  --resume-session-at <lastEntryUUID(turn k)>
  --mcp-config <empty mcpServers> --strict-mcp-config
```

  Same executable/environment/cwd resolution as the main process (extract `makeLaunchPlan()` from `startProcessIfNeeded`). No prompt on stdin beyond the initialization/control handshake; no RepoPrompt MCP server; no RepoPrompt MCP routing ownership; never `--rewind-files`, `--no-session-persistence`, or a synthetic prompt; `--resume-drops-turn` is not used in v1 (it only describes a single-discarded-turn case; S4 records its behavior). Built by a pure package helper (`ClaudeCompatibleBranchArguments`) that also becomes the home of the existing interactive argv rules rather than duplicating them. Fork attempt boundary = successful spawn; anything after is potentially ambiguous. Wait for the earliest of `system/init` (must report `session_id == childUUID`), child store file present and stable, process exit, or a bounded timeout; close stdin; wait for exit; then verify.
- Execution seam: `NativeAgentRuntimeControlling` unchanged; add an opt-in actor protocol `ClaudeSessionForking` (`performSessionFork(_:) async throws -> ClaudeSessionForkOutcome {observedInitSessionID?, exitStatus, stderrTail, childStoreURL}`) implemented by `ClaudeNativeProcessSessionController` on a **fresh, never-installed** instance (a running source controller's `process == nil` guard cannot be reused) and forwarded by `ClaudeCompatibleNativeSessionAdapter`; `ClaudeAgentModeCoordinator.prepareControllerForBranching(session:)` mirrors the Codex analog.
- Verification authority is the CLI's own store, read-only, via a core actor `ClaudeNativeSessionStore` using package-pure `ClaudeSessionStoreChain` (parses only `uuid`, `parentUuid`, `type`, `isSidechain`, `sessionId`, `message.role`, content block kinds; unknown conversation-bearing kinds fail closed) and `ClaudeSessionStoreLocator` (config dir from `CLAUDE_CONFIG_DIR` in the resolved launch environment else `~/.claude`; cwd encoding per S8; no whole-home search). Pre-fork: stable source snapshot + raw-byte digest; selected anchor on the main chain (walk from the leaf via `parentUuid`); every retained checkpoint's `lastEntryUUID` (and prompt UUIDs when present) appears in order; recompute retained/omitted counts and impact and **require renewed confirmation if they differ from the displayed summary**. Post-fork: child chain root→leaf equals the source sub-chain (by uuid if S2(b) shows uuids are preserved, else by `(type, role, content hash, order)`), `sessionId` on child entries is the child (or source, per S2(d)), no extra main-chain entries; source bytes unchanged. Off-main, streaming, `O(source + child bytes)`; five-second bound for a partial JSONL tail to settle; an unverified tail never becomes valid by timeout.
- One attempt, no retry. After any post-spawn failure, one read-only verification of the preassigned child file: fully valid ⇒ proceed; otherwise fail naming the child ID. CE never deletes or writes into the Claude store; orphans are reported and logged. The CE branch session file is written only after child verification (commit point = the child session's atomic save). If the child is saved but activation/index publication fails: `Branch created; could not open it` with **Open created branch** — never another fork.
- Qualification gate (`ClaudeBranchCapabilityProbe`, core actor; rules in package-pure `ClaudeCompatibleBranchSupport`): version floor `>= 2.1.258`; a cheap flag-presence probe (`--resume-session-at <nil-uuid>` without `--resume`: stderr "requires --resume" ⇒ present, "unknown option" ⇒ absent) for fast rejection; then a cached **isolated behavioral probe** that forks a CE-authored two-turn fixture inside a temporary `CLAUDE_CONFIG_DIR`, requiring child == prefix and fixture bytes unchanged. Cached in memory by executable fingerprint + version + launch profile; positive results persist for that identity, negative results until the executable/profile changes or the user chooses **Check again**; never per reply row; state visible as `Checking Claude Code branching support…`. Checkpoints are captured regardless of capability. No exact-version allowlist. **Contingency (S1/S0):** if the CLI cannot start/resume/fork a synthetic fixture without credentials or network in an isolated config dir, the behavioral probe is infeasible and the gate is floor + flag probe + post-fork chain validation.

### 3.5 Exact resume for Claude tree members

- `AgentNativeResumePolicy { exactOrFail, allowFreshFallback }` resolved before consuming the next prompt from the existing provider-neutral tree resolver: branch child, root known to have branches, or unavailable tree evidence ⇒ `exactOrFail`. Threaded into `ClaudeAgentModeCoordinator.startControllerSession`; `shouldRetryFreshStartWithoutResume` returns `false` under `exactOrFail` for all five currently recoverable errors; no replacement controller, handoff injection, or adoption of an unexpected native ID. Standalone Claude recovery is unchanged.
- Preflight for `exactOrFail`: acquire the existing exact-resume preflight ownership; leave composer text, attachments, and transcript untouched; start with documented `--resume <stored-id>`; require the observed runtime ID to equal the requested ID (`recordObservedSessionID` rejects an unexpected ID before publishing); only then admit the user turn and clear the draft. Failure ⇒ `AgentBranchOperationError.claude(.exactResumeFailed)` → "This conversation could not be reopened. Your message was not sent." A live process may be reused only when its binding is already proven to be that exact session. Validate in Phase 4 the order of transcript commit vs controller start in the Claude run path; nothing may be appended on failure.

### 3.6 View-model transaction (`AgentModeViewModel`)

`branchFromTurn` becomes shared prologue → provider fork step → shared epilogue, without touching the Codex fork body beyond mechanical extraction: prologue = selection-pin validation, `beginBranchOperation`, draft/attachment preservation, `flushSaveThrowing`, `validateBranchOperation`; fork step = `performCodexBranchFork` (today's code) or `performClaudeBranchFork` (capability re-check → `prepareControllerForBranching` → locate/parse source store → pre-validate → spawn → post-validate → re-read source), each returning `AgentNativeForkResult {nativeChild: .codex(threadID, rolloutPath?) | .claude(sessionID, storeURL), childLedger}`; epilogue `finishBranchCreation` = `AgentSessionBranchSnapshotBuilder` (existing prefix builder, lineage with `sourceNativeTurnRef` + `sourceProviderKind`, Claude: `providerSessionID = child`, `claudeTurnCheckpoints` rebound to the child, Codex ids nil), persist, restore into the tab, system note, `endBranchOperation`. `BranchOperationPin` carries `AgentNativeBranchIdentity` instead of a Codex string; `validateBranchOperation` after every suspension. `replyBranchConfirmation` is replaced by `branchSelection(turnID:tabID:) -> AgentBranchSelection?`; the Oracle count is resolved through the VM's Oracle reference, not a view closure. The existing switch operation is retained behind `switchConversationPath(to:target:)`.

### 3.7 Unified conversation tree picker

- One SwiftUI sheet `AgentConversationTreePicker` (resizable, ~840×560, min 720×480), owned by `AgentModeView` through `AgentConversationTreePickerState` (replaces `AgentReplyBranchConfirmationState`); it replaces both `AgentConversationBranchMenuPresenter` (deleted) and `AgentReplyBranchConfirmationSheet` (deleted). - Visibility: the shortcut opens the picker for **any active Agent Mode tab** — supported contexts get the full tree; a tab with no persisted session shows `Complete a turn to create a branch.`; unsupported providers/ownership states get the read-only turn outline from the in-memory transcript with every action disabled and the exact `staticUnavailableReason` in the footer. The titlebar button is shown when `staticUnavailableReason == nil` (including Claude with qualification pending) or lineage exists (a surviving singleton branch counts), and hidden for intrinsically unsupported sessions without lineage.
- Shape: a single `NSOutlineView` (`AgentConversationTreeOutlineView`) in the Pi `/tree` shape — completed turns nest under paths; a branch path attaches beneath the row that owns its `sourceTurnOrdinal` along the ancestor chain and lists only its post-fork turns (shared prefixes appear once); a source turn no longer retained shows `Turn N (not retained)`; deleted roots/sources use the placeholders in §3.2. Node IDs are compound `(sessionID, turnID)` because a CE turn UUID legitimately appears in several paths; ⏎ on a turn inside the active session's retained prefix branches the **active** native session at that CE turn. Right pane: the selected turn's prompt and stored final conclusion through existing read-only Markdown rendering. Rows show ordinal, a whitespace-normalized prompt snippet (≤160 visible chars), availability indicator, and `N branches` badges.
- Data: topology from index records only (name, `savedAt`, lineage, counts, `agentKindRaw`); the active path's turns from `sessions[tabID].transcript.turns` with per-turn `AgentSessionBranchGate.evaluate`; inactive paths load on demand through the existing cold-session loader, cached for the picker's lifetime keyed by session id + `savedAt`, at most two full inactive snapshots; late/cancelled loads never publish into a different target; browsing starts no native controller. Coalescing uses inherited identities and `branchPrefix` equality, never snippet matching.
- Model (`AgentConversationTreePickerModel`, `@MainActor ObservableObject`, pure reducers tested): phase `loading | ready | failed`; per-path `notLoaded | loading | loaded | failed`; selection; expanded IDs; operation `idle | branching | switching | preCommitFailed | nativeIndeterminate | childSavedNotOpened`. States also cover no completed turns, unsupported/unavailable, incomplete/unreadable tree evidence (current path from memory, switching disabled, branching still allowed).
- Actions are row-type driven: active-path eligible turn ⇒ **Branch** / **Branch anyway**; active path header ⇒ `Current path`; inactive path or its turn ⇒ **Switch to this path** (creation disabled: `Open this path before creating a branch.`); deleted/unreadable/elsewhere-open ⇒ preview where available, action disabled with the existing help text. Switch closes the picker and sends nothing; create closes after activation. Keyboard: ↑/↓ rows, →/← expand/collapse or move into/out of a node, ⏎ the enabled primary action (including Branch anyway; no second dialog), ⎋ closes while idle or failed and is ignored once submission starts, ⇥ ordinary focus traversal; key repeat cannot submit twice. Default selection: reply entry ⇒ that turn; shortcut/titlebar ⇒ latest completed turn of the active path.
- Structured safety footer (`AgentBranchSafetySummary`, exact strings finalized in Phase 2 and pinned by tests): `Keeps turns 1–{k} · sets aside {m} later turn(s)` (`nothing set aside` when m = 0); impact `Read-only exploration` / `Changed files: a, b, … and N more` (8-path cap, expandable) / `May have changed files`; `Conversation only — files, Git state, and workspace selections are not rolled back.`; `{n} Oracle chat(s) stay with the source path — this branch can read their results but must start new chats to continue.` (source path, not "original", because branches can be sources); buttons `Branch` / `Branch anyway` / `Switch to this path` / `Current path`; stale `The conversation changed. Review the updated branch details.`; provider `Native branching is currently available only for local Codex and Claude Code sessions.`; runtime `Checking Claude Code branching support…` / `Branching needs Claude Code 2.1.258 or newer.` / `Claude Code branching could not be verified for this executable.` During submission `Branching…` / `Switching…`. Existing exact-copy tests in `AgentBranchUITests` are re-targeted to these fields — a deliberate contract change, not a weakening.

### 3.9 Error handling and edge cases

| Situation | Behavior |
|---|---|
| Tree index unavailable | Picker `.failed`; current path from memory; switching disabled; branching allowed; exact resume still required. |
| Inactive path load fails | Row-level error; other paths unaffected; read-only **Refresh** retries reads only. |
| Zero completed turns | `No completed turns yet.`; Branch disabled. |
| Selection pin stale or preflight changed counts/impact | Footer refreshes and shows the stale copy; requires a new explicit activation. |
| Probe unknown at open | Turns show the runtime-unknown state; UI updates when the published result lands. |
| Fork process exits before the child exists | `Claude could not create the branch: {stderr tail}. Nothing was changed.` |
| Child exists but invalid / timeout after spawn | One verification; else `Branching finished with an unverified Claude session ({id}). The original conversation is unchanged; the branch was not saved.` |
| Source changed between reads | Fail; no branch saved. |
| Child saved, activation fails | `Branch created; could not open it` + **Open created branch**. |
| App quit mid-fork | Possible Claude-side orphan file only (documented). |
| Older build opens a Claude branch | Decodes; badge shows; gate reports provider unsupported; re-save drops `claudeTurnCheckpoints` and `sourceProviderKind` but keeps lineage; continuing Claude trees on an older build is unsupported. |
| Session ID mismatch after exact resume | Rebind ledger + visible system note; never silent. |

## 4. Material disagreements and how they were resolved

| # | Item | Lane positions (initial) | Outcome |
|---|---|---|---|
| A | Lineage wire format | One `branchOrigin` with legacy key vs separate `claudeBranchOrigin` key. Round 1: both lanes conceded to the *other's* position. Round 2: both settled on **one object**, decisive reason: a separate key is silently dropped whenever an older build re-saves, permanently detaching the branch (silent state loss); the key-name mismatch is a readability cost contained by the in-memory name, a coding-key comment, and dispatch-by-binding. | **Resolved** (§3.2). Flip condition: a code audit finding a consumer that feeds `sourceCodexTurnID` into a Codex runtime call without a binding guard. |
| B | Nested lineage in the index | Schema bump + full re-projection vs targeted on-demand repair. | **Resolved: bump** (verified single invalidation authority; repair would be a second projection writer with partial states). Phase 1 must time the rebuild. |
| C | Hidden-flag capability gate | Floor + stderr flag probe vs exact-version allowlist + isolated behavioral probe. | **Resolved: floor + flag probe + cached isolated behavioral fork probe; no allowlist** (an allowlist darkens the feature after every CLI auto-update; a stderr check proves only parser knowledge). Contingency if the isolated probe needs credentials/network (§3.4). |
| D | Compaction and sidechains | Per-turn eligibility (Codex parity) vs whole-conversation lockout. | **Resolved: per-candidate eligibility** with persisted lockout state, ambiguous-segment rejection, and a spike-triggered fallback to whole-conversation lockout if S5 fails (§3.3). |
| E | Seal evidence and prompt UUID | Seal on stream `result`, JSONL read at branch time, prompt uuid optional vs prompt uuid required + resume anchor + native-store read at every seal. | **Resolved by Phase 0:** both lanes reject per-turn disk reads and agree sealing uses the stream `result`; S3 proved the CLI persists a caller-supplied stdin `uuid`, so a verified prompt UUID is required without `--replay-user-messages` — see below. |
| F | Picker visibility | Available only for branch-capable providers or trees >1 vs any Agent Mode tab. | **Resolved by judgment** (§3.7): shortcut always opens the picker (read-only + reason when unsupported); titlebar button hidden for intrinsically unsupported sessions without lineage; reply icon hidden when structurally unsupported. |
| G | Tree shape | Two panes vs single Pi-style outline. | **Resolved: single outline** with coalesced shared prefixes, compound node IDs, and active-session creation on retained-prefix turns (§3.7). |

**E — resolved by Phase 0: prompt UUID required.**

- *Position 1 (required).* Prefix equality proves that the child matches a native cut, not that the cut represents the selected CE turn; only a verified prompt UUID (caller-supplied stdin `uuid`, or the `--replay-user-messages` echo, correlated by UUID and never by text) ties the native chain to CE's submitted input. Turns without one are unavailable. Would accept "optional" only if the spike shows another explicit submission-to-chain identity (e.g., a correlated request ID) gives equivalent turn-boundary evidence across all qualified history shapes.
- *Position 2 (optional).* The CLI anchors truncation on the kept turn's last entry, so stream order is not needed to segment the chain: branch preflight walks the main chain from disk, splits it at prompt-shaped user entries, requires exactly one segment per CE turn, takes each segment's last entry as the anchor, and cross-checks the streamed assistant uuid; mandatory stdin-uuid/replay plumbing buys hardening, not correctness. Would flip to "required" if S3/S6 show routine turns persist main-chain user-role entries CE cannot classify (injected reminders, absorbed messages), making segment counts diverge from CE turns.
- *Recommendation and Phase 0 outcome.* Treat Position 1 as the default because its flip condition is unlikely while Position 2's is plausible: Claude Code is known to persist non-prompt user-role main-chain entries (tool results, injected system-reminder text), so "prompt-shaped" segmentation is fragile. S3 proved that both standard and replay-enabled submissions persist the caller-supplied stdin `uuid`; replay additionally echoes it. Therefore future Claude checkpoint work must require the caller-supplied UUID without enabling `--replay-user-messages`. Position 2's segment cross-check remains an additional fail-closed validation.

Minor points resolved by judgment: `--resume-drops-turn` excluded from v1; fork argv mirrors the source launch profile minus MCP (S1 may reduce it); error type is renamed with a typealias rather than wrapped; `NativeAgentRuntimeControlling` is unchanged (resume policy lives in the coordinator; identity check in `recordObservedSessionID`); handoff glyph `arrowshape.turn.up.right`; the owning contract document is broadened and renamed to `docs/context/conversation-branching.md` in Phase 5 with its AGENTS.md route updated; the Phase 0 report lives in `docs/investigations/` (local, not staged).

## 6. Risks and limitations

- Hidden CLI flags may change semantics or vanish: version floor, flag probe, isolated behavioral probe, and post-fork chain validation fail closed at branch time, never at resume time; a fork whose child differs is rejected before any CE session is written.
- Index schema 7 triggers one full stub-based rebuild per sessions folder at first launch (existing mechanism; timed in Phase 1).
- Exact-copy and `shouldPresent` tests are deliberately replaced (call out in the PR).
- Removing the `NSMenu` costs one sheet on the quick-switch path; accepted for a single UI.
- Older builds re-saving a Claude branch keep lineage but drop `claudeTurnCheckpoints`/`sourceProviderKind`; continuing Claude trees on an older build is unsupported.
- No durable fork journal: a crash mid-fork can leave an orphan Claude session file (reported, never deleted by CE).
- Compaction/subagent support beyond what the spike proves is a follow-up, not an automatic fallback path.

## 10. Phase 0 outcome

Phase 0 is complete. The final approved opt-in diagnostic ran against installed Claude CLI 2.1.258 with temporary `HOME`, `CLAUDE_CONFIG_DIR`, and working directories; credential variables were removed, network proxies were fail-closed, RepoPrompt MCP was absent, subprocess output/time were bounded, and each scenario made at most one fork attempt. The harness discovered source stores empirically rather than assuming cwd encoding. Deterministic hardening now makes every post-fork check search the isolated config for the exact child UUID, separates physical presence from cwd/location qualification, and rejects malformed/incomplete JSONL and dangling parent references. The recorded live report predates these post-shutdown discovery and integrity fields, so it cannot retroactively prove absence outside the watched source-derived location; the hardening does not alter the fail-closed qualification result. Redacted evidence remains intentionally unstaged at `docs/investigations/claude-native-branching-2.1.258.md`.

- **Blocking S0 + S2(a): failed closed.** The source store was discoverable and the prompt-free process accepted the CE-shaped initialize control request, but no matching `system/init` event or durable child file appeared at the watched source-derived location. After the initial timeout the harness closed stdin and observed the process exit during bounded EOF grace. Because that live report predates all-location child discovery, it does not prove global absence; it does prove that Claude CLI 2.1.258 did not satisfy the qualification contract under the tested observation path. Phases 3–4 are blocked; Phases 1–2 remain eligible.
- **S1:** supported. The hidden `--resume-session-at` flag is recognized and, without `--resume`, exits nonzero with `Error: --resume-session-at requires --resume`. The minimal fork argv in §3.4 remains parser-valid.
- **S2:** the source bytes remained unchanged, but child-prefix equality, UUID preservation policy, child `sessionId`, and `system/init` identity were inconclusive because no child materialized. Strict chain checks reject an empty or truncated child.
- **S3:** supported. Standard and replay-enabled submissions both persisted the caller-supplied stdin UUID in the empirically discovered store; replay additionally echoed it and the streamed user UUID matched disk. This resolves §4 E in favor of requiring the caller-supplied UUID without replay.
- **S4:** inconclusive. The valid `--resume-session-at <retained-anchor>` plus `--resume-drops-turn <dropped-prompt>` pair ran, but it mutated the isolated source store and exited nonzero without a classifiable non-JSON error; the harness restored the fixture. `--resume-drops-turn` remains excluded from v1.
- **S5–S6:** compaction, sidechain, and retained non-prompt-user ancestry remain inconclusive because S0 failed. The S6 fixture places the reminder in retained parent ancestry and derives expected membership by walking `parentUuid` links.
- **S7:** a bogus anchor failed without a child and reported `No message found with message.uuid of: <uuid>`; a prompt-entry/mid-turn anchor accepted initialization but produced no child before timeout and EOF grace.
- **S8:** source stores were empirically found for spaces/Unicode and symlink cwd shapes, but no child materialized, so the fork-location result remains inconclusive.
- **S9:** the live report classified this as supported because a missing source failed fast and produced the recognized redacted error `No conversation found with session ID: <uuid>`. That report predates separation of exact-name physical candidates from cwd qualification, so the no-child portion is treated as inconclusive until a future approved run; the current harness requires positively confirmed zero candidates.
- **S10:** observational and inconclusive. The harness terminated the process group only after the initialize control response and found no child bytes afterward; this is not a deletion guarantee.
- **S11:** the prompt-free start fired a configured `SessionStart` hook and returned the matching initialize control response, with no prompt, RepoPrompt MCP, assistant event, or model/tool-request evidence. Hook firing is a confirmed limitation.

The production branching/runtime path remains unchanged and no Claude feature gate was enabled.
