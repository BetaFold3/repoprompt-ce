## Motivating incident (verified)

- Cursor ACP discovery (capability mode) returns ~35 bare base models; per-model axes (context/reasoning/fast) come only from the `cursor/list_available_models` extension call, parsed into the **in-memory-only** `CursorModelParameterCatalog`. Base models persist (`ACPDynamicModelStore`); axes do not.
- A Cursor auth expiry made discovery throw before the extension call; `CursorACPModelPollingService.performRefresh` swallowed the error silently. Result: bare models kept rendering from the persisted snapshot while every parameter submenu (Oracle preset pickers included) vanished for the whole app launch, with no evidence trail.
- Two additional wipe paths exist: `apply(response:)` replaces the whole catalog with empty on one malformed response, and `clearForMethodNotFound()` wipes on `-32601`.
- `agent_manage list_agents` projects one start target per bare model. Bracketed variants (`cursor:<base>[context=272k,reasoning=max,fast=true]`) validate and start (bracket stripped for matching; `reasoning_effort` overlays the unique `thought_level` param), but nothing advertises the axes or grammar.
- OMP is a first-class agent with discovered flattened IDs (`cursor/gpt-5.6-sol-max-fast`, ~202 options) but has zero presence in the Oracle model layer: no `AIModel` case, no `AIProviderType`, no `AIProviderFactory` route, no picker rendering. Cursor's Oracle path (`AIModel.cursorCustom` → `CursorCLIProvider` → fresh headless ACP session in `ask` mode, no tools/MCP) is the parity template.

## Phase A — OMP models as Oracle presets

1. **Blocking fix**: `OhMyPiACPHeadlessAgentProvider.beforePrompt` unconditionally awaits `prePromptMCPRouteIsReady`, which can never succeed with `includeRepoPromptMCPServer: false` — every Oracle request would stall the full timeout, then fail. Gate the route wait on `config.includeRepoPromptMCPServer` (exact predicate: the wait verifies a connection back to a server that was only injected when that flag is true). Existing MCP-enabled Agent Mode behavior is unchanged; add an injectable route-check closure so tests can prove the closure is never invoked for Oracle configs.
2. **Shared extraction (D1)**: new `Infrastructure/AI/Providers/HeadlessCLIStreamBridge.swift` with `ActiveHeadlessAgentProviderStore<T: AnyObject>` and the stream-bridge/completion-accumulation helpers currently inlined in `CursorCLIProvider`; migrate Cursor byte-equivalent in behavior. No pre-existing Cursor CLI provider suite was present, so `CursorCLIProviderTests` now directly locks the existing permissive completion, prompt-only/no-MCP config, legacy empty-response diagnostic, and exactly-once lifecycle behavior; failures are extraction regressions, never reasons to weaken the test.
3. **Types**: append the non-raw Codable enum case `AIProviderType.ohMyPi` (display "Oh My Pi", CLI-backed — no API-key/base-URL configuration) without renumbering or pretending it has a raw integer; append `AIModel.ProviderIndex.ohMyPi = 14` while Cursor remains `13`. Add `AIModel.ohMyPiCustom(name:)` with raw `ohmypi_custom_<exact wire ID>`; decode only nonempty suffixes; preserve `/`, `:`, case, and flattened suffixes verbatim; `modelName` byte-identical to the registry raw value; display metadata via new `ACPAIModelCatalog.ohMyPiModelOption(for:)` with raw-ID fallback. No static fallback option (unlike Cursor's Auto) — an empty registry contributes zero models.
4. **Execution**: new `OhMyPiCLIProvider: AIProvider` mirroring `CursorCLIProvider`'s lifecycle on the shared bridge. Per request: warm the registry, fail closed per D3, then a fresh `OhMyPiACPHeadlessAgentProvider` with `includeRepoPromptMCPServer: false`, exact canonical model string, `workspacePath: nil`, no-tools suffix applied even when the incoming system prompt is empty, no attachments/resume. ACP permission/tool rejections propagate as request failures; partial text is never converted into a successful result. Route `.ohMyPi` in `AIProviderFactory` (no signature change).
5. **UI**: new shared `OhMyPiModelMenuBuilder` (namespace grouping per P5) used by `AIModelDropDown` and `OptimizedModelPicker`; availability strictly via the existing `isOhMyPiConnected` release gate plus the existing DEBUG smoke override — persisted registry snapshots alone must never make OMP selectable. Append OMP options after existing entries (the `availableModels.first` fallback defines an implicit default; prepending would change it). A persisted OMP selection still decodes/displays when disconnected; executing it returns the existing normalized configuration/auth error.

## Phase B — Cursor parameter-catalog durability + diagnostics

1. New `CursorModelParameterStore` (P1 schema: `schemaVersion: 1`, `updatedAt`, canonicalized `models[]` of base + parameters with id/category/defaultValue/options/description). `NSLock` transaction, injectable `UserDefaults`, JSON encode/decode, `removeObject` on authoritative clear; tests use a dedicated suite, never `.standard`.
2. `CursorModelParameterCatalog`: injected store; synchronous hydration (launch warm alongside `warmStandardStoreIfNeeded`, lazy hydration under the existing lock as backstop); `apply` returns `ApplyResult` (`applied(didChange:)` / `rejectedMalformed`) with the atomic parser per P2; `replace(with:persist:)` stays the single mutation point and keeps posting notifications outside the lock; `Status` snapshot (`idle/cached/refreshing/live/stale(kind)/unsupported/disabled`, failure kinds `authentication/timeout/malformedResponse/discovery/extension`, `hasUsableCatalog`, `lastSuccessfulRefresh`, `lastAttempt`); new `.cursorModelParameterCatalogStatusDidChange` kept strictly separate from the data-change notification so status churn never invalidates menus. `test_restoreSnapshot` never touches real defaults.
3. `CursorACPModelPollingService`: record and classify failures instead of swallowing (auth → `authentication`, bootstrap/support → `discovery`, extension timeout → `timeout`, structural rejection → `malformedResponse`, other → `extension`; cancellation during shutdown is not a failure); centralize any fallback phrase-matching next to the existing method-not-found predicate; rate-limit logs (error on reason transition, debug on repeat); sanitized details only — never raw payloads/prompts/credentials. Bounded retry backoff on failure streaks (~15s → 300s cap, injectable base, reset on success) so re-authentication recovers menus without an app restart. A successful extension refresh must still publish the bare-model snapshot even when the extension call failed.
4. Settings status row per D2, bound to the status notification.

Failure matrix (target behavior): auth expiry / launch failure / timeout / malformed → submenus keep rendering from the retained (possibly persisted) catalog, status explains why, backoff retries; method-not-found / valid-empty → submenus disappear by design with an accurate status ("this Cursor version doesn't expose model parameters" vs "no parameterized models"); corrupt or unknown-version persisted record → ignored, not deleted, next success overwrites; feature flag off → existing single gate in `CursorModelMenuBuilder`, no double-gating.

## Phase C — `list_agents` Cursor parameter metadata

Additive/optional field; start-target count and order unchanged; declare the new boolean tool argument (default `false`).

## Risks and migration

- The `ohmypi_custom_` prefix and `AIModel.ProviderIndex` assignments are one-way doors: verify index `14` is unassigned, keep Cursor at `13`, and ensure no looser `fromModelName` matcher shadows the prefix. `AIProviderType` is a non-raw Codable enum, so `.ohMyPi` has no integer raw value; older binaries cannot decode payloads containing that unknown provider case unless the decoding boundary explicitly tolerates it. Do not describe this as raw-value compatibility or assume unknown providers are ignored, and never rewrite unknown preset raw values.
- Stale persisted Cursor axes may briefly advertise values Cursor removed; bracket validation strips unknown params, status exposes `updatedAt`, next successful poll replaces atomically. Accepted; no TTL (a TTL reintroduces the disappearance symptom).
- OMP tool isolation has no verified prompt-only mode (D4); residual risk is bounded by no-MCP + fail-closed approvals + no-tools suffix and should be covered by an integration smoke test proving a tool-seeking prompt cannot mutate a fixture workspace.
- ~202 OMP options: namespace grouping keeps menus tractable; measure menu-build once with the real catalog before adding any cache.
- Rollback is clean both directions: new UserDefaults key ignored by old builds; `ACPDynamicModelProviders` untouched.
