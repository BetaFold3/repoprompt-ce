Quick model selection and quick handoff for Agent Mode

RepoPrompt CE now has two keyboard-first model search panels. One panel changes the model in the current session. The other panel sends the last completed assistant reply to a new session.

Executive summary

The change removes several mouse steps from two common Agent Mode tasks. You can now search for a model, choose an effort level, and confirm the choice with the keyboard. You can also start a handoff from the last completed assistant reply with the same type of search panel.

What you can expect

Before this change

  • You used the model menus in the input bar.
  • You used a small handoff button under a reply.
  • You moved through several menus to choose a provider, model, and effort.
  • You used the mouse for most of the flow.

After this change

  • You open a focused search panel with one shortcut.
  • You type model, provider, effort, or raw identifier text.
  • You use the arrow keys and Enter to confirm.
  • The handoff panel uses the newest eligible completed assistant reply.

Main behavior

Fast model search

A query such as Fable high can find a Claude Fable model with High effort. A query such as Sol xhigh can show the normal and Fast Sol choices.

The normal choice stays before the Fast choice when their search score is equal.

Safe current-session changes

The quick model picker uses the same model-control rule as the input bar. It keeps the provider-family lock and the knowledge-session policy.

It checks the live session and model again before it saves the choice.

Safe handoff target

The quick handoff panel refuses an active reply. It skips failed and cancelled turns. It also requires the exact remote host row when the source session is remote.

Stable panel behavior

The search panel captures one catalog snapshot when it opens. Each key press only ranks that snapshot. The panel and the Agent navigation panel cannot be open at the same time.

Keyboard rules

  • ↑ and ↓ move the selection.
  • Enter confirms the selected row.
  • The first Esc clears a non-empty query. The next Esc closes the panel.
  • Digits are search text. The panel does not use digits as result shortcuts.
  • An empty query selects only the exact current model row. If no current row exists, Enter does nothing.

→
2. Choose a destination

The same search index shows local or cached remote destination models.

→
3. Create the handoff

The source tab stays pinned. The existing handoff service creates the destination session.

Major technical decisions

Decision Reason Effect
Use one HUD with two modes. The model picker and handoff picker need the same search and keyboard behavior. The UI stays consistent. The commit action remains different for each mode.
Do not refactor the existing navigation HUD now. The Oracles applied the rule of two. The new HUD first copies proven UI patterns. A later change can extract a shared form with evidence from both HUDs. The feature avoids unrelated risk in the shipped navigation panel.
Build a pure model-leaf index. Provider catalogs already own model names and effort rules. The index must not add a second model catalog. New and future models can appear without hard-coded search rules.
Keep ranking snapshot-based. The user asked for a fast panel. Network work and provider discovery would add variable delay. Each key press only parses and ranks local strings.
Use one shared current-model commit seam. The input bar and the HUD must use the same side-effect order and live checks. The two model-control surfaces are less likely to drift.
Pin handoff work to the source tab. An async handoff can run while the active tab changes. The handoff cannot silently use a new active session after a tab switch.
Do not use digits as row shortcuts. Model names and versions contain digits, such as 5.6. All digits remain valid query text.
Keep Default selectable. The HUD can show Default as the exact current Codex row. The final fix makes commit validation use the same full live catalog. Default does not become a dead row when concrete models also exist.
Do not cancel a handoff after commit starts. The destination can already exist when cancellation arrives. A blocking overlay hides the HUD without cancelling the handoff task.

Observed in session The dual-Oracle planning rounds and implementation review produced these decisions.

Major turns in the work

1

The investigation found reusable parts

The code already had a keyboard HUD pattern, a string search matcher, provider catalogs, family locks, and a handoff service. The plan reused these parts instead of making a new model system.

2

Two Oracles planned the feature independently

OracleB and OracleC received the same prompt. They challenged each other on the main design differences. The final plan used a sibling HUD, a pure index, a shared commit seam, and a source-pinned handoff.

3

Scoped workers implemented the plan

The implementation was split into bounded work areas. A fresh review then checked the integrated result. This followed the user request to use workers and keep the main agent in an orchestration role.

4

A fresh review found four correctness issues

  • Empty-query Enter could select an arbitrary model.
  • A parameterized Cursor selection could lose its exact raw identifier.
  • A failed or cancelled assistant turn could become a handoff target.
  • A blocking approval overlay did not always remove a committing HUD at once.

The implementation corrected all four issues before the first validation summary.

5

The dual-Oracle implementation review found one blocker

The Codex catalog could show a Default row. The HUD could select it, but commit validation removed that row when concrete models existed. This made Default a dead row.

6

A scoped worker fixed the blocker

The worker kept Default selectable. It changed commit validation to use the full live catalog. This was the smaller semantic fix because the HUD and handoff paths already treated Default as valid.

7

Both Oracles approved the final correction

OracleB returned APPROVE_WITH_NONBLOCKING_FOLLOWUPS. OracleC returned APPROVE. Both agreed that the dead-row defect was resolved.
