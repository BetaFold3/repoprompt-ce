Right Utility Panel:
review changes and read agent output without leaving RepoPrompt

Phases 1 and 2 are implemented as an uncommitted macOS feature: a responsive Changes | Preview panel that combines a live, worktree-aware Git review surface with native Markdown reading and a security-hardened HTML renderer.

Executive summary

The application now has the foundation for an in-app review loop: watch an agent edit code, inspect the live diff, stage reviewed files, and open the Markdown or HTML report the agent produced—all beside the conversation that caused the work.

Panel behavior
Dock or overlay

It protects transcript width, becomes an overlay when space is tight, and remembers the preferred width.

Diff behavior
Live + actionable

Working-tree and base comparisons, staged/unstaged/conflict groups, split mode, review tracking, and safe file-level index actions.

Document behavior
Markdown + HTML

Semi-rendered or fully rendered Markdown, Obsidian-style navigation, images, outlines, and rendered/source HTML.

Trust model
Fail closed

HTML uses a custom URL scheme, non-persistent WebKit data, network blocking, strict navigation policy, and explicit one-document script consent.

What this changes for your daily workflow You should be able to remain in RepoPrompt for the two most common post-agent activities: reviewing the code that changed and reading the report or notes the agent wrote.
Current delivery state The feature is present only in the working tree. Nothing from this implementation is staged or committed, and no visible app launch was performed in the reporting pass.

Opening and sizing the panel

  • Use the toolbar’s right-sidebar icon, choose View → Utility Panel, or press ⌥⌘0.
  • Drag the panel’s left edge to resize it between its compact and expanded widths; double-click the resize strip to reset.
  • With sufficient space, the panel docks beside the transcript. In a narrow window, it becomes a trailing material overlay with no dimming scrim.
  • Panel visibility is per window. The selected segment and review/preview state follow the active tab. Preferred width is stored in global settings.
  • Animations respect Reduce Motion, and the new controls include explicit accessibility labels and values.

Observed in code AgentUtilityPanelLayout, AgentUtilityPanelPresentationStore, AgentUtilityPanelCommands, and ContentViewToolbarContent.

The Changes experience

Default review
Working Tree

Files are grouped as Staged, Unstaged, and Conflicts. A partially staged file can correctly appear twice with a different patch in each group.

Committed agent work
vs Base

Select an explicit branch, tag, SHA, or revision such as HEAD~3. The panel never silently guesses a base.

Review controls

  • Repository and worktree targeting: a root picker appears for multi-root workspaces, while a chip names the agent worktree actually being reviewed.
  • Fast filtering: All, Staged, Unstaged, and—when applicable—Conflicts pills narrow the working-tree view without changing repository membership.
  • Unified and split diff: split layout is available at an effective diff width of at least 560 points; narrower panels automatically return to unified mode.
  • Intraline emphasis: changed word ranges are highlighted inside added and removed lines.
  • Expandable context: hunks start compact and can request more surrounding lines, with bounded fallbacks for very large files.
  • Viewed tracking: an eye button marks each file reviewed; the footer shows progress. A later edit changes that state to “viewed, edited since” rather than pretending the review is still current.
  • Sticky orientation: comparison controls, section identity, file headers, freshness, and refresh controls stay findable while the diff scrolls.

Safe index actions

  • Stage or unstage individual files, or apply the section-level action to all rows currently represented.
  • Rows show local pending state and do not visually jump sections until Git confirms the authoritative refresh.
  • Immediately before mutation—and again after every suspension—the implementation checks that the reviewed content and repository generation are still current.
  • If an agent edits a file after you reviewed it, the panel refreshes and flashes the row instead of staging unseen content.
  • Conflicts are not stageable through the ordinary checkbox. A separate, confirmed Mark resolved action records the current resolution.
  • Jujutsu repositories expose working-copy review without pretending they have Git’s staging area.
Worktree safety is intentionally visible A session-bound worktree never silently falls back to the main checkout. While it is being prepared, the panel waits. If it becomes unavailable, the user must explicitly choose “Show Workspace Checkout Instead,” and a warning chip remains visible afterward.

Observed in code and tests AgentChangesRepository, AgentChangesPanelViewModel, AgentPanelCheckoutResolver, VCSIndexMutationBackend, GitBackendStagingTests, and the diff projection suites.

The Preview experience

Finding a document

The Preview segment presents a searchable, narrow-panel-friendly list rather than a folder tree. Documents written during the active session are grouped first under Written This Session; other Markdown and HTML files in the workspace follow. The Changes view also surfaces the newest created or overwritten document as a quiet “written by agent · View →” banner.

Markdown
Semi or Rendered

Semi keeps every source character—including #, **, backticks, list markers, and blockquotes—while applying readable typography. Rendered provides a conventional reading surface.

HTML
Rendered or Source

Rendered uses the secure WebKit surface. Source shows selectable, highlighted HTML and degrades to plain monospace past the highlighter’s density ceiling.

Markdown details

  • The semi-rendered compiler decorates the verbatim source, with the structural invariant output.string == source; copy and paste therefore round-trips valid Markdown.
  • A document-outline button lists headings and scrolls to the selected section in either Markdown presentation.
  • Wiki links such as [[design]] and relative Markdown links navigate inside the preview when the destination remains within the same logical root.
  • Rendered mode supports local images and Obsidian image/note embeds through root-scoped resolution.
  • A green status dot indicates live reload; an orange dot means the watcher degraded to a slow re-check.
  • Scroll identity is tied to the document, not each revision, so ordinary live reloads preserve the reader’s place.
  • Documents above the bounded preview size are sent to an editor instead of forcing synchronous text layout to hitch the application.

HTML details

  • Scripts and network access are blocked by default.
  • Clicking an external HTTP(S) link in scripts-blocked mode opens a warning dialog before the system browser can be used.
  • Run scripts is an explicit, one-document permission. It is cleared when navigating away.
  • When scripts are enabled, access narrows to the selected document’s non-hidden folder subtree, while network, forms, frames, workers, popups, and persistent storage remain blocked.
  • External links are cancelled without even presenting a browser confirmation while scripts are on, because page JavaScript can synthesize clicks.

Observed in code AgentPreviewPanelView, SemiRenderedMarkdownCompiler, ObsidianEmbedProcessor, AgentPreviewMarkdownImageProvider, SecureHTMLPreviewConfiguration, and HTMLPreviewNavigationPolicy.

Refresh and performance model

  • One porcelain-v2 status read establishes section membership; patch loading enriches that model rather than defining it.
  • Git metadata invalidations are fingerprint-gated, but direct content events bypass that gate because editing an already-modified file may not change porcelain status.
  • Patch text is loaded only for expanded files. Cache identity includes checkout, target, comparison, fingerprint, file, context, and content revision.
  • FSEvents batches use trailing debounce with a maximum age of about 500 ms, so continuous agent writes cannot postpone refresh forever.
  • A healthy watcher uses no timer. A degraded watcher falls back to slow polling, with reconciliation on activation/wake and after mutations.

Major turns and decisions from the implementation sessions

These are the choices that materially changed the design or prevented a plausible but unsafe implementation.

01

The mockup became a direction, not a pixel copy

The initial HTML attachment first appeared only as a file icon. After the root-level mockup was rendered, the refined “Option 2” visual language won: one Changes/Preview segment, quiet cards, sticky orientation, and no document tabs.

Observed in session The repository’s existing runtime-sidebar vocabulary was reused so the feature feels native to RepoPrompt rather than bolted on.

02

A custom responsive panel replaced the obvious .inspector() choice

SwiftUI’s inspector was feasible, but the final behavior needed protected transcript width, programmatic artifact deep links, font-scaled clamps, per-window presentation, and a narrow-window overlay. The custom layout expresses those contracts directly.

03

Working Tree remained the default, but vs Base moved into Phase 1

Agents may commit as they work. A panel that only shows uncommitted changes can look empty precisely when there is substantial work to review. The base is nevertheless explicit because a silently wrong comparison is worse than asking once.

04

Content events bypass Git fingerprints

A key correctness finding from the planning duel was that porcelain status can remain unchanged while an already-modified file changes repeatedly. Direct filesystem events therefore force content revision and patch eviction instead of being discarded by a status fingerprint.

05

Staging became a separate capability with a review-to-stage preflight

Only Git implements the optional index protocol. More importantly, the panel does not trust a row merely because it was displayed: it rechecks revision, target generation, represented path scope, and the authoritative set before every mutation or retry.

06

Semi-rendered Markdown shipped in Phase 1

This was treated as the Preview’s signature experience, not deferred polish. Decorating the original source string makes formatting misses recoverable while making text corruption structurally impossible.

07

HTML preview was designed as an untrusted-content boundary

A plain WKWebView.loadFileURL would expose too much of a checkout, especially when agents can create symlinks. The custom scheme, descriptor-based reads, CSP, content rules, and navigation policy were chosen before enabling scripts.

08

The user expanded the delivery to Phase 2 before review

Split diff, viewed tracking, filters, intraline emphasis, context expansion, Markdown images/embeds, heading navigation, conflict resolution, custom revision comparison, and narrowly scoped script opt-in were implemented before the final review wave.

09

The dual-Oracle review produced a safety and liveness fix wave

Independent reviewers converged on scope escape, refresh starvation, event-loss, index preflight, and HTML time-of-check/time-of-use risks. Three workers repaired the staging, filesystem, and WebKit boundaries before the focused suites were rerun.

10

A low-level WebKit crash changed the file-read implementation

A fixed-argument @_silgen_name("fcntl") binding was invalid for C’s variadic function on arm64. The implementation moved to Darwin’s proper fixed-arity overlay, after which the affected scheme-handler suite completed successfully.

Observed in session and design record This rule is now recorded so future maintainers do not reintroduce the unsafe binding.

Orchestration note The two review requests were placed in one batched turn, but the client tool loop awaited one blocking Oracle stream before dispatching the next. RepoPrompt supports concurrency; the effective limitation was the caller’s execution loop. Future time-sensitive duels should run each Oracle lane inside its own detached worker/tab and poll both sessions.

Safety properties worth preserving

Git mutations
Scoped

Current and rename-origin paths are validated. Copy sources are not mutated. Unexpressible write scopes disable mutation instead of widening it.

HTML resources
Descriptor-based

Resolve → O_NOFOLLOW open → fstat → path containment recheck → bounded read happens as one operation.

Navigation
Allowlisted

Forms, frames, popups, unknown schemes, remote loads, and synthetic scripted egress are cancelled; ambiguous preparation fails closed.

Specific reviewed fixes

  • Rename-origin scope escape: a file renamed into a represented root can no longer stage deletion of an out-of-scope origin.
  • Retarget identity: checkout scope and substitution changes now invalidate the target even when the filesystem path is unchanged.
  • Idle wait liveness: retarget cancellation signals parked refresh waiters so a spinner cannot hang indefinitely.
  • Lock retry: one index.lock retry reruns the entire safety preflight rather than blindly replaying the Git command.
  • Event starvation: continuous writes flush within the maximum batch age; FSEvents history gaps become full-resync triggers.
  • Scheme-handler TOCTOU: containment is rechecked on the opened descriptor, not on a path that can be swapped between check and read.
  • Window targeting: a toggle notification without a valid window ID now targets no window rather than every window.
Script opt-in is intentionally powerful When you choose “Enable once,” agent-authored JavaScript can read the selected HTML document and non-hidden assets below its folder. The boundary blocks network and common browser escape surfaces, but this is still a trust decision. Keep scripts off unless the report genuinely requires them.

How to test and see the effect, step by step

Use a disposable repository The Changes panel can mutate Git’s index. Do not begin manual staging tests in a checkout containing valuable unstaged work.

  1. Build the current source

    Run the coordinated development build from this repository:

    make doctor
make dev-build

    To launch the app yourself, run make dev-run. If you ask an agent to perform the visible launch or relaunch, it must request approval immediately before doing so.

  2. Create a disposable Git workspace with mixed states

    Run this in one Terminal session, then copy the printed path:

    DEMO="$(mktemp -d)/rpce-panel-demo"
mkdir -p "$DEMO/Sources" "$DEMO/docs"
cd "$DEMO"
git init -b main
git config user.name "RepoPrompt Panel Demo"
git config user.email "panel-demo@example.invalid"

cat > Sources/Greeting.swift <<'EOF'
struct Greeting {
    static let message = "Hello"
}
EOF

cat > docs/notes.md <<'EOF'
# Linked note

This is a second document.
EOF

git add .
git commit -m "Base"
git switch -c feature/panel-demo

printf '\n// unstaged edit\n' >> Sources/Greeting.swift

cat > docs/report.md <<'EOF'
# Agent report

## Summary

- A readable **Markdown** document
- A link to [[notes]]
- Source markers should remain copyable in Semi mode
EOF

git add docs/report.md
printf '\nThis line was added after staging.\n' >> docs/report.md

cat > docs/report.html <<'EOF'
<!doctype html>
<meta charset="utf-8">
<title>Panel HTML demo</title>
<style>body { font: 18px system-ui; padding: 2rem }</style>
<h1>HTML report</h1>
<p id="status">Scripts are blocked.</p>
<p><a href="https://example.com">External link</a></p>
<script>
document.getElementById("status").textContent = "Local script ran.";
</script>
EOF

printf 'Demo workspace: %s\n' "$DEMO"
git status --short

    Expected setup: Greeting.swift is unstaged, report.md appears in both staged and unstaged state, and report.html is untracked.

  3. Open the workspace and show the panel

    Load the printed demo folder into RepoPrompt and open an Agent Mode tab. Click the toolbar’s right-sidebar icon, use View → Utility Panel, or press ⌥⌘0.

    Expected: the panel opens on the right with Changes and Preview segments. Resize the window to see it switch between docked and overlay presentation; drag the left strip and double-click it to reset.

  4. Verify Working Tree review

    Keep Working Tree selected. Confirm Staged and Unstaged groups appear, and that docs/report.md appears in both with different patches. Try All/Staged/Unstaged filters.

    Expand files, increase context, and mark files viewed with the eye button. Expected: the footer progress changes; editing a viewed file again changes its eye state to indicate it needs review.

  5. Verify split diff and intraline highlighting

    Widen the utility panel to its expanded width. Select Split.

    Expected: old and new sides align, with word-level emphasis inside changed lines. Below the 560-point effective width gate, Split disables and the panel returns to Unified.

  6. Verify live refresh

    With the app and Terminal visible, append another line:

    printf '\n// live edit %s\n' "$(date +%s)" >> "$DEMO/Sources/Greeting.swift"

    Expected: the row and expanded patch refresh within roughly half a second under continuous activity, without requiring the manual refresh button.

  7. Verify safe staging and unstaging

    Use a file checkbox, then the Staged/Unstaged section action. Watch git status --short in Terminal after each click.

    Expected: only represented files move, the row shows pending feedback before authoritative refresh, and working-tree contents are not lost when unstaging. To test the review preflight, edit a file from Terminal immediately before clicking Stage; the panel should refresh rather than stage unreviewed content.

  8. Verify vs Base and custom revisions

    Select vs Base, choose main, and confirm the flat comparison. Then choose Custom revision… and enter HEAD~1 or a valid SHA.

    Expected: the panel validates the revision and never preselects a base you did not choose. Staging controls are absent in vs-Base mode.

  9. Verify Markdown Preview

    Switch to Preview, search for report.md, and open it. Toggle Semi and Rendered.

    Expected: Semi retains visible Markdown markers while styling the text; copying the whole document produces valid original Markdown. Rendered hides markers. The outline button jumps to “Summary,” and [[notes]] opens the linked document inside the panel.

  10. Verify secure HTML behavior

    Open report.html in Preview.

    • In default Rendered mode, the status must remain Scripts are blocked.
    • Clicking the external link should show a warning before the browser can open.
    • Choose Source to see selectable highlighted HTML.
    • Return to Rendered, click Run scripts, read the warning, and choose Enable once. The status should become Local script ran.
    • While scripts are enabled, clicking the external link should do nothing—not even summon the browser prompt.
    • Navigate away and return; the one-document script grant should be cleared.

  11. Verify the agent-artifact shortcut

    In the same Agent Mode tab, ask the agent to create or overwrite a new file such as docs/session-report.md.

    Expected: the newest created/overwritten Markdown or HTML artifact appears as a banner in Changes. Clicking View → switches to Preview and opens that exact document. Pure modifications intentionally do not create banner noise.

  12. Optional edge-state checks

    • Open a plain non-Git folder: expect a friendly “not a repository” state.
    • Use a repository with no first commit: expect the unborn-HEAD state, with supported staging semantics.
    • Use an agent session bound to a worktree: expect the worktree chip and no silent main-checkout fallback.
    • Create a disposable merge conflict: expect an ordinary staging checkbox to be disabled and a distinct, confirmed Mark resolved action.
    • Open a Jujutsu root: expect working-copy review without Git staging controls.

Operational and integration impact

  • Dependencies: no third-party dependency or lockfile change was observed. HTML rendering uses the system WebKit framework.
  • Settings: the existing global settings document gains an additive preferred-panel-width value.
  • Persistence: panel tab state remains in memory; it was deliberately not added to the durable session schema. Preferred width persists.
  • Database/migrations: none observed.
  • Feature flag: none observed; the panel is mounted in Agent Mode.
  • Compatibility: staging is capability-driven. Git gains index mutations; Jujutsu remains non-staging.
  • Runtime: one changes controller owns refresh/watch state while the panel is mounted; Preview owns a single-file watcher for the selected document.
