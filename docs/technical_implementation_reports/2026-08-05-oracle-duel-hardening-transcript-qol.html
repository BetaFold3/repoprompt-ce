Executive summary

The work resolves two correctness/usability failures and adds four supporting improvements. Oracle chats cloned into a handoff now belong to the destination session and carry usable replacement IDs. App-owned Agent Mode connections may once again overlap two Oracle calls under a harness that previously serialized them. Preset-backed Oracle results no longer hand the judging agent the resolved provider/model identity, while the human-facing popover and tool-card UI remain unblinded.

What you can expect from the change

Before

  • A Claude Code–driven main agent could serialize two Oracle calls, so the pill never reached Oracle · 2.
  • A handed-off session retained dead Oracle IDs and could not continue the cloned chats.
  • The judging agent was directly told the resolved model identity for preset-backed lanes.
  • Long Oracle turns could hit context limits without an honest preflight or useful usage breakdown.
  • Large Oracle replies consumed the main agent's context unless manually exported.
  • Old assistant replies were collapsed with no transcript search; diffs were horizontally clipped/scrolled and used only the system mono font.

After

  • Two app-owned Agent Mode Oracle sends can overlap, and a batch consultation API gives a durable two-lane path.
  • Handoff clones are owned by the destination, mapped to new IDs, and old IDs produce a corrective hint during the live destination tab.
  • Agents receive preset alias/UUID, while you retain resolved model attribution in the Oracle UI.
  • Known exact context windows get a fail-fast budget check; every result exposes honest usage/reserve metadata.
  • response_mode and paged chat-log controls let the main agent consume only the tail—or no inline reply—without losing the full export.
  • Assistant-only search expands and navigates matches; expansion is available on demand; diff wrap and transcript code font are configurable.
The model footer remains visible to you. Human UI attribution still comes from chat-session and assistant-message metadata (lastSendModelDisplayName, lastResponseModelDisplayName, and message modelName). What changed, in easy-to-understand terms

1. Oracle chats survive handoff as real, owned conversations

Source session
Only chats owned by this agent session are eligible.
→
Atomic clone
New chat IDs are created and stamped with the destination owner.
→
Destination handoff
Payload IDs are rewritten and an old→new mapping table is appended.
  • The destination Agent Mode session identity is allocated before Oracle cloning.
  • Only source-owned chats are cloned, and ownership is rechecked after loading the full chat.
  • If any clone cannot load or persist, all clones are rolled back and the handoff fails loudly instead of producing a partial destination.
  • Structured references use the new chat IDs; surrounding prose gets a mapping table with short and full UUID forms.
  • An old ID is not silently redirected. During the live destination tab it returns an error that points to the replacement ID.

Observed in code Key paths: AgentModeViewModel.swift and OracleViewModel.swift.

2. Dual-lane concurrency works without lying to external MCP clients

The canonical ask_oracle tool is still non-read-only because it spends money, creates state, and is non-idempotent. Only app-owned Agent Mode connections—classified from server-established run purpose—receive a connection-specific readOnlyHint: true. This allows Claude Code's scheduler to overlap two calls without advertising the same claim to external clients. Observed in code

  • The app still enforces at most two concurrent Oracle streams per tab.
  • A single consultations request can fan out independent new chats and returns results in input order.
  • require_distinct:true can reject a batch before launch when two lanes resolve to the same preset/model.
  • Additional consultations queue behind the two-stream limit; no detach/polling job abstraction was added.

3. Preset-backed Oracle lanes are blinded to the judge, not to the operator

Agent-facing result serialization recursively removes both the new UI identity keys and legacy model_id/model_name fields whenever a result is preset-backed—including nested batch and legacy shapes. The app captures an internal UI sidecar first, so Oracle tool cards, the sidebar, and the popover can still show resolved identity to you.

Main agent receives

  • Preset alias and preset UUID
  • Neutral capability/usage information
  • Response text or export metadata

You still receive in the UI

  • Resolved model attribution in message footers
  • Lane/session identity in Oracle popover and sidebar
  • Human-readable Oracle tool-card attribution

4. Oracle context and response size are now controllable

Request budget

The exact immutable packaged request is estimated before mutation/provider work, including history, selection, frozen diffs, system/preset text, output reserve, and tokenizer margin.

Selection control

Continuation sends support current, none, or send-local explicit_slices. Send-local slices never mutate the shared selection.

Response control

full returns everything; tail returns about 2,000 final characters; none returns metadata only. Trimmed replies are always auto-exported.

  • Only an exact known context window may trigger oracle_context_overflow; provider fallback estimates do not pretend to be authoritative.
  • The preflight uses a conversation revision fence so a chat that advances between packaging and reservation fails retryably before mutation.
  • Busy implicit candidates fail before creating a new chat, avoiding orphan chats or active-pointer changes.
  • Usage echoes include input tokens and output reserve; context window/percentage appear only when exact metadata exists.
  • oracle_chat_log accepts part: head|tail|both, per-message max_chars, and a total ceiling, with self-describing truncation.

5. Assistant transcript review is faster without hydrating tool output

  • A floating magnifying-glass control searches completed assistant messages in the transcript model.
  • Results have a counter and previous/next controls. Navigating to a result expands the row, waits for layout, scrolls it to center, and flashes it.
  • The adjacent ellipsis menu offers Expand All Assistant Replies and Restore Automatic Collapsing.
  • Expansion state is ephemeral and resets when leaving the session. Tool/activity output remains out of scope.

6. Transcript diffs can wrap and use a chosen fixed-pitch font

  • Diff cards have a local Wrap checkbox, and Settings → Appearance has a persistent Wrap Diff Lines toggle. The default remains off.
  • Wrapped height is measured with width-aware TextKit logic and cached by content, width bucket, wrap mode, and resolved-font fingerprint.
  • Copying still preserves the original unwrapped source text.
  • Settings → Appearance → Transcript Code Font offers system monospaced plus installed fixed-pitch faces.
  • Uninstalled or invalid faces fall back silently; render and syntax-highlight caches incorporate the resolved font fingerprint.

Major turns in the session

These turns materially changed the design or caught defects that would otherwise have shipped.

The missing “Oracle · 2” indicator became a diagnostic clue. The app already supported two streams; the indicator disappeared because one main-agent harness serialized tool calls before they reached the app. This shifted the fix from Oracle streaming internals to per-connection tool metadata.
Prior handoff work was recognized as restart-only, not handoff continuity. Earlier preset inheritance preserved a lane across restart in the same durable agent session. Handoff creates a new agent session, so cloned Oracle ownership and ID rewriting required a separate correctness fix.
Identity attestation was deliberately simplified after user pushback. An initial proposal used server-side fingerprints to prove distinct hidden resolutions. The user correctly questioned whether that over-engineered a bias-control feature. The final design removes the obvious result leak and defers attestation until a real silent-resolution incident exists.
Cross-examined Oracle lanes converged on a smaller response API. They rejected permanent cursor paging for exported immutable replies, kept export-as-retrieval, and selected simple head/tail/both chat-log controls plus source-side response trimming.
The transcript scope was narrowed to the high-value resident data. Once code inspection proved assistant text was never stripped, “always expanded” and hydration infrastructure were dropped. Search plus on-demand expansion became the first QoL slice.
The first post-implementation review found two ship-blocking defects. UI-only identity keys still leaked through some agent-facing serializations, and the default unwrapped diff-height path contained a deterministic floating-point-to-integer crash. Both were fixed and regression-tested.
A re-review exposed five residual correctness/details issues. Legacy preset identity fields, dishonest fallback-window usage, reservation staleness/orphan behavior, incomplete full-UUID mapping prose, and TextKit wrap-style refresh were corrected in a final remediation pass.
The review itself hit a context-input ceiling. Shared selection had ballooned from implementation activity. The reviewer was retried with only the fresh diff artifacts. This was an operational demonstration of why response/selection budgeting matters.

How to test and see the effect, step by step

Prerequisite: rebuild the debug app, then relaunch it. The repository requires coordinated make dev-* commands. A visible app launch/relaunch requires explicit user approval immediately before the action, so it was not performed during this report-only pass.

A. See two Oracle lanes overlap

  1. Open an app-owned Agent Mode session with two enabled Oracle presets.
  2. Ask the main agent: “In one turn, consult OracleA and OracleB concurrently as two new chats. Give each a detailed independent question and wait for both.”
  3. Open the Oracle popover while both are running. Expected: the pill briefly reads “Oracle · 2”, and two rows show simultaneous streaming. Very short replies may finish too quickly to observe.
  4. Repeat using one batch consultation with two entries and require_distinct:true. Expected: ordered lane results, no more than two active streams, and early rejection if both entries resolve to the same lane.

B. Confirm handoff continuity

  1. In a source Agent Mode session, start a named Oracle chat and ask at least one follow-up. Record the MCP-facing chat ID.
  2. Handoff the agent session to a new destination tab/provider.
  3. Inspect the handoff payload or ask the destination agent to identify the old→new Oracle chat mapping. Expected: both readable short-ID and full-UUID mapping rows are present.
  4. Ask the destination agent to run oracle_chat_log on the new ID, then continue that chat. Expected: history loads and the continuation succeeds under the destination owner.
  5. Try the old ID in the same live destination tab. Expected: no silent redirect; the error names the replacement ID.

C. Verify “blind to the agent, visible to me”

  1. Ask a preset-backed Oracle question and inspect what the main agent reports from the tool result. Expected: preset alias/UUID are available; resolved provider/model ID and name are absent from the agent-facing result.
  2. Open the Oracle popover and inspect the assistant message footer. Expected: you still see the resolved model name.
  3. Inspect the corresponding Oracle tool card in the transcript. Expected: human-facing attribution remains available because the app captured it before wire redaction.

D. Exercise request and response budget controls

  1. Continue an existing Oracle chat with selection_mode:"none". Expected: no current workspace selection or review diff is attached for this turn; shared selection is unchanged.
  2. Continue again with selection_mode:"explicit_slices" and one small file/range. Expected: only that send-local slice is packaged; the shared selection still does not change.
  3. Ask for a long response with response_mode:"tail". Expected: about the final 2,000 characters return inline, plus line/character counts and a full-response export path.
  4. Repeat with response_mode:"none". Expected: no response body inline, but export and size metadata remain retrievable.
  5. Read the same chat using oracle_chat_log with part:"head", then "tail", then "both", using a small max_chars. Expected: deterministic excerpts and a truncation marker explaining what was omitted and how to retrieve more.
  6. Use an intentionally oversized selection against a lane with exact capability metadata. Expected: oracle_context_overflow occurs before a chat turn/provider call, with major contributors and remedies. Lanes without exact metadata intentionally skip this rejection.

E. Search and expand assistant transcript replies

  1. Open a long Agent Mode transcript containing several completed assistant replies, including older collapsed ones.
  2. Click the floating magnifying-glass button labeled Search assistant replies.
  3. Type a phrase found in an older assistant reply; use Return or the up/down buttons. Expected: a match counter updates, the matched reply expands, scrolls into view, and flashes. Tool-call output is not searched.
  4. Open the adjacent ellipsis menu and choose Expand All Assistant Replies, then Restore Automatic Collapsing. Expected: bulk expansion is immediate and non-animated; leaving the session resets this ephemeral state.

F. Toggle diff wrapping and change the code font

  1. Open a transcript tool card containing a unified diff with a very long line.
  2. Toggle the card's Wrap checkbox. Expected: long lines soft-wrap, horizontal scrolling is removed, height updates after layout, and copied text remains unwrapped.
  3. Go to Settings → Appearance → Display Options and toggle Wrap Diff Lines. Expected: this persisted setting controls transcript diffs and tool code-block fallbacks; default is off.
  4. Go to Settings → Appearance → Transcript Code Font and choose another installed fixed-pitch face. Expected: Agent Mode/chat code blocks and diffs update using the selected face. “System Monospaced” restores the current default.

Risks, limitations, and deliberate deferrals

Observed limitations

  • The implementation is not committed, staged, or running in the current app build.
  • No full-suite test run or live visual smoke test is recorded.
  • The old→new handoff error-enrichment mapping is in memory. After app relaunch, an old ID degrades to a normal not-found error; the new ID remains the correct continuation ID.
  • Agent-facing identity blinding is bias control, not a security boundary. An agent with filesystem/shell access may still discover configuration.
  • Unknown or fallback-only model context windows do not trigger pre-send overflow rejection.

Deliberately deferred

  • Persisting handoff ID mappings across app relaunch.
  • A shared cross-batch per-tab scheduler beyond the existing two-stream cap and per-item concurrency errors.
  • Detach/poll/await Oracle job surfaces.
  • Identity fingerprints or server-side resolution attestation.
  • Automatic history compaction.
  • Cursor-based Oracle message paging.
  • Tool/activity transcript search and hydration.
  • Diacritic-insensitive assistant search.
  • Perfect line-height handling for exotic fallback glyphs.

Open questions preserved from the plan

  • Whether the Claude Code tool queue is process-global or per sub-agent.
  • Retention and access boundaries for exports if export-as-paging becomes the canonical workflow.
  • Whether CLI-backed Oracle providers preserve any provider-side session state that changes the stateless packaging assumptions.
