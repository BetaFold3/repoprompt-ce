Technical implementation report

Phase 7: agent lifecycle wait efficiency

This report explains the provider-aware automatic wait change for RepoPrompt CE Agent Mode.

Report date: 2026-09-16 Implementation staged No commit created No external assets

Outcome

Phase 7 replaces one universal two-minute lifecycle wait with a small provider-family policy.

When a caller omits a timeout, a Claude parent gets 180 seconds.

A Codex parent gets 600 seconds.

Every other or unresolved parent gets 180 seconds.

A lifecycle call starts a worker, waits for a worker, or continues a worker.

MCP is the local protocol that lets an agent call RepoPrompt tools.

The policy uses the authenticated parent run.

It does not guess from the worker model, client name, role label, or transport.

Early completion, cancellation, and user-input states still return immediately.

The selected time is an upper limit for waiting.

It is not a required sleep.

It is also not a promise about a provider cache lifetime.

The staged implementation has focused test, lint, format-check, and product-build evidence from the implementation session.

What to expect

Automatic calls

Omit timeout for start or wait.

Omit timeout_seconds for a steering call that waits.

RepoPrompt returns a root object like this for an active automatic wait:

{
  "wait_policy": {
    "mode": "automatic",
    "timeout_seconds": 600,
    "parent_family": "codex"
  }
}

A Claude parent uses 180 and "claude".

An unknown parent uses 180 and "unresolved".

Only automatic mode includes parent_family.

Explicit and poll calls

timeout: 45 produces mode: "explicit" and a 45-second value.

timeout: 0 produces mode: "poll".

Poll returns the current snapshot without waiting.

timeout: null means the same thing as omitting the field.

Values from 0 through 14,400 seconds are valid.

A value above 14,400 returns a validation error.

RepoPrompt does not silently reduce an oversized value.

Detached and remote calls

A detached start does not wait.

It therefore has no wait_policy object.

The remote gateway uses a conservative 630-second envelope for an omitted start because it cannot know whether that start will detach.

The gateway still caps its own response at 900 seconds.

A response timeout at that remote boundary does not stop an already accepted worker.

Provider meaning

Only .claudeCode maps to the Claude row.

Only .codexExec maps to the Codex row.

Claude-compatible vendors do not automatically get the Claude value.

They use the other row unless future code deliberately changes the table.

A standalone, remote, legacy-routed, or ambiguous caller correctly resolves as unresolved.

How to test it now

Run these commands from the repository root.

Use the coordinated make dev-* commands.

If the conductor reports global-wait, wait for its ticket.

Do not start a direct Swift or Xcode command as a substitute.

1. Check the local setup

make doctor

Fix only setup problems that this command reports.

2. Run the smallest core test

make dev-core-test FILTER=InteractiveMCPClientSessionCancellationTests

This checks automatic CLI envelopes, JSON null, explicit values, and poll behavior.

3. Run the policy contract test

make dev-test FILTER=AgentLifecycleExecutionContractTests

This checks every current provider kind, the frozen parent family, the 180/600/180 table, the four-hour maximum, and the result metadata.

4. Run the lifecycle service tests

make dev-test FILTER=AgentRunMCPToolServiceWaitTests
make dev-test FILTER=AgentRunMCPToolServiceSteerResumeTests
make dev-test FILTER=AgentRunWorktreeStartTests

These cover wait, steer-with-wait, multi-wait, and start paths.

5. Run the transport and presentation tests

make dev-test FILTER=RemoteCommandTranslatorTests
make dev-test FILTER=AgentRunResponsePresentationTests
make dev-test FILTER=MCPRequestIdempotencyAgentRunServiceTests

These check gateway deadline selection, wait_policy through response trimming, and replay behavior.

6. Run the user-facing contract tests

make dev-test FILTER=AgentControlToolCardPresentationTests
make dev-test FILTER=ToolCatalogSnapshotTests
make dev-test FILTER=WorkflowPromptCatalogTests

These check tool-card text, tool schema text, and the managed workflow prompts.

7. Check style and build each affected product

make dev-format-check
make dev-lint
make dev-swift-build PRODUCT=RepoPrompt
make dev-swift-build PRODUCT=repoprompt-mcp
make dev-swift-build PRODUCT=repoprompt-gateway

Each command should exit with status zero.

A filtered test command must report that it ran tests.

A zero-test command is not a pass.

8. Optional broader test

make dev-test-parallel

This is the full root test lane.

It is broader than the focused Phase 7 checks.

9. Optional manual behavior check

Use an active MCP-bound Agent Mode parent for this check.

A standalone or remote caller is expected to produce the unresolved 180-second policy.

Do not launch or relaunch a visible app through an agent without explicit approval.

If you deliberately launch the debug app yourself, use rpce-cli-debug, not the production CLI.

  1. Select Claude as the active parent. Start or wait for a child without a timeout. Expect mode: "automatic", timeout_seconds: 180, and parent_family: "claude".
  2. Select Codex as the active parent. Repeat the call. Expect timeout_seconds: 600 and parent_family: "codex".
  3. Use timeout: null. Expect the same automatic result as an omitted timeout.
  4. Use timeout: 0. Expect mode: "poll" and no parent_family.
  5. Use timeout: 45. Expect mode: "explicit", timeout_seconds: 45, and no parent_family.
  6. Use timeout: 14401. Expect an error before a new worker starts or an existing worker receives a steer.
  7. Start several detached workers. Then call one multi-wait without a timeout. Expect one root wait_policy object, not one object per worker.
