Executive summary

The original symptom was that Cursor exposed GPT‑5.6 Sol only as a single default entry—medium reasoning, 272k context, Fast off—even though Cursor itself supports more choices. The implementation fixes that limitation end to end while preserving the existing external model ID grammar.

Before

  • RepoPrompt did not send Cursor’s opt-in capability flag.
  • The model registry saw one bracketed default per model, such as gpt-5.6-sol[context=272k,reasoning=medium,fast=false].
  • A caller requesting a non-default bracket could be silently mapped back to the default.
  • No UI controls existed for model-specific reasoning, context, or Fast mode.

After

  • Cursor sessions advertise _meta.parameterizedModelPicker: true.
  • The registry receives clean base IDs such as gpt-5.6-sol.
  • The UI discovers and shows each model’s actual parameter domains.
  • Selections are applied and echo-verified one setting at a time, with rollback on failure.
  • Malformed, unsupported, or conflicting choices fail loudly instead of being coerced.
Practical outcome: a user can select GPT‑5.6 Sol, choose 272k or 1M context, choose the advertised reasoning level, and explicitly keep Fast off or turn it on. RepoPrompt enforces the full selected state before sending the prompt. Observed in code

How it works, in human terms

The feature separates three concerns: discovery for the picker, a stable model identity for RepoPrompt, and verified runtime application to Cursor.

1. Discover

A background Cursor polling session calls cursor/list_available_models with a 10-second timeout and stores parameter metadata in memory.

→

2. Compose

The UI converts a user’s submenu choices into one full identity, such as gpt-5.6-sol[context=1m,reasoning=high,fast=false].

→

3. Enforce

The run selects gpt-5.6-sol, validates Cursor’s live selectors, applies each value, and checks the echoed snapshot before prompting.

The safety transaction

  1. Parse: reject malformed brackets, duplicates, empty components, or unrepresentable values.
  2. Select the base model: use the clean model ID that Cursor advertised.
  3. Read live selectors: parameters appear dynamically after model selection; the controller treats the latest complete snapshot as authoritative.
  4. Pre-validate: every requested key and value must exist in Cursor’s post-selection selectors.
  5. Apply: set only values that differ; apply fast last.
  6. Verify: require each response to echo the exact requested value, then perform a final state check.
  7. Rollback on error: restore changed parameters in reverse order and restore the previous model if the model was switched. If rollback itself fails, the error explicitly warns that Cursor may retain a partial global configuration.
Key implementation seams
  • ACPAgentProvider.initializeClientCapabilityMetadata is a default-empty provider hook; only Cursor supplies the capability metadata.
  • CursorBracketModelID owns the parse/compose grammar and forces Fast to the end.
  • CursorModelParameterCatalog parses the proprietary catalog into a thread-safe, in-memory snapshot and notifies the UI.
  • ACPAgentSessionController.setCursorSessionModelSerialized owns the runtime transaction.
  • CursorModelParameterPickerViewModel maps catalog categories to user labels and composes complete bracket selections.
  • AgentExternalMCPRunStarter treats Cursor model strings separately from Codex model suffixes and can overlay a validated Cursor thought-level value.
OpenCode compatibility: shared ACP machinery was extended through a default-empty hook and provider-gated branches. OpenCode does not receive the Cursor capability metadata, and dedicated regression tests pin its behavior. Observed in code Observed in tests

Major turns in the investigation and implementation

The strongest design choices came from protocol evidence that invalidated plausible—but wrong—first approaches.

Turn 1 — The initial diagnosis changed

The first report suggested Cursor exploded configurations into IDs such as gpt-5.6-sol-high-fast. A live probe of cursor-agent 2026.07.23-e383d2b showed the real legacy shape: one bracket-serialized default per model. This explained why RepoPrompt only saw medium reasoning and Fast off.

Turn 2 — Both initial Oracle mutation plans were disproved

Legacy mode rejected synthesized bracket variants and clean IDs. Capability mode rejected all bracketed IDs. Therefore neither “synthesize a better bracket ID” nor “send a composite bracket in capability mode” could work.

Turn 3 — The actual protocol appeared after selecting a model

In capability mode, selecting a clean base model caused the session’s configOptions to grow model-specific selectors. GPT‑5.6 Sol exposed context, reasoning, and fast; GPT‑5.2 exposed reasoning and fast. This became the runtime source of truth.

Turn 4 — Global persistence raised the safety bar

Live probes showed that Cursor remembers model parameters across sessions. Because Fast has a price consequence, the implementation moved from ordinary sequential writes to an abort-and-rollback transaction with Fast last.

Turn 5 — Post-implementation duel found nine hardening gaps

Two independent Oracle reviews returned “do not ship” and “ship with fixes.” Their converged findings exposed stream timing, incomplete rollback, kill-switch gaps, stale catalog behavior, timeout coverage, selection bleed, and other edge cases. All nine were fixed and given regression tests.

Major decisions and why they were chosen

DecisionChosen behaviorReasoningConsequence
Capability injection A defaulted provider hook; Cursor returns parameterizedModelPicker=true. Keeps Cursor-specific knowledge out of shared controller branching and leaves other providers empty by default. Small, testable seam; OpenCode’s initialize payload stays unchanged.
Durable model identity Keep cursor:<base>[k=v,…]. Existing persistence and external callers already understand a base plus parameters. No data migration or public wire-schema change.
Catalog placement Discovery/polling only, never required by normal run bootstrap. The proprietary extension is needed to build the picker, not to apply a selected model. Catalog failure hides pickers without breaking runs.
Runtime authority Use live post-selection session selectors. The catalog’s currentValue is metadata/default data, not the session’s live state. Every run validates against what Cursor actually advertises at that moment.
Bare-base selection Inherit Cursor’s remembered settings and surface them. Resetting to catalog defaults would make the proprietary extension a run dependency and fight Cursor’s own preference ownership. Diagnostics show effective values; inherited Fast produces a visible system warning.
Preference ownership No duplicate RepoPrompt per-model preference store in v1. Two persistent owners would drift. The full bracket is already the desired state when users choose explicit settings. Cursor remains the remembered-state owner; RepoPrompt enforces explicit bracket selections.
Invalid input Fail loudly. Lenient fallback would recreate the original silent-coercion bug. Malformed brackets, unknown keys, invalid values, and effort conflicts are user-visible errors.
Emergency fallback UserDefaults-backed kill switch, default on. The Cursor extension is proprietary and version drift is plausible. Capability injection, catalog fetch, and Cursor effort overlay can all be disabled together without rebuilding.

Risks, limitations, and compatibility notes

Observed risks

  • Global Cursor state: model parameter writes can persist beyond RepoPrompt and affect terminal Cursor sessions.
  • Private extension: cursor/list_available_models is not advertised by ACP initialize and may drift across Cursor releases.
  • Registry generation flip: upgrading produces clean IDs; downgrading may temporarily pair older bracketed state with newer persisted registry state until polling self-heals.
  • Legacy behavior changed intentionally: non-default parameter requests that were silently coerced now fail explicitly on an old agent.

Scope intentionally deferred

  • No agent_manage expansion or parameter metadata enrichment.
  • No persisted structured catalog; pickers appear after live discovery.
  • No generic second-provider parameter metadata abstraction.
  • No schema changes to AgentModelOption, the dynamic model store, or the public agent_run/agent_manage payloads.
