Executive summary

RepoPrompt CE now has a second, deliberately fresh Agent Mode profile named Knowledge. It is designed for questions such as “help me understand these documents,” “compare two expert opinions,” “research the latest evidence,” or “turn this investigation into a durable note.”

The ordinary New Session action remains the coding-oriented Agent Mode experience. Knowledge mode is available through a small secondary menu, so it is discoverable when needed without adding coding workflows, research presets, or debate controls to every new session.

What can we expect from this change?

A quieter research agent

The agent sees workspace reading, search, note editing, Oracle consultation, and recovery tools—not the broad coding, shell, Git, delegation, settings, and worktree surface.

Current information when useful

Provider-native web search remains available when the selected provider supports it and the existing user preference enables it. The prompt asks for primary sources, dates, links, and explicit uncertainty.

Images and PDFs remain useful

Claude keeps native Read for images, screenshots, PDFs, and other non-text media. Codex keeps view_image for images and screenshots; the UI and prompt do not overstate Codex PDF support.

Dual opinions without a debate machine

The agent may consult OracleA and OracleB independently and concurrently, synthesize directly by default, and use one or rarely two anonymized critique rounds only when disagreement warrants it.

Durable output follows the workspace

When useful, the agent writes a note with apply_edits into the active workspace. A project workspace yields a project-local note; an iCloud or Obsidian-rooted workspace yields a note there.

Normal coding work should not move

The primary button, global standard-session shortcut, ordinary system prompt, broad coding tool policy, and standard provider behavior remain on the existing path.

Inferred product benefit: a smaller, purpose-specific surface should reduce irrelevant tool choice and keep the model’s attention on evidence and synthesis. This report does not claim a measured quality or token improvement; behavioral evaluation still requires real usage.

How it works

1. Persisted session identity

AgentSessionProfile has two values: standard and knowledge. The profile is threaded through full persistence, lightweight restore headers, sidebar metadata, run leases, headless leases, provider-controller identity, handoff behavior, and MCP connection policy.

Session serialization is now version 7 and the metadata index schema is version 6. Older sessions with no profile decode as standard. Explicit null and unknown present values fail closed so corrupted or future data cannot silently become a different profile.

2. Exact RepoPrompt tool ceiling

ToolKnowledge purpose
get_file_treeOrient within the active document or repository workspace.
file_searchFind paths and text across workspace roots.
read_fileRead source, Markdown, configuration, logs, and other text with RepoPrompt context tracking.
apply_editsCreate or update durable notes and other user-requested text artifacts.
oracle_utilsResolve named Oracle presets exactly.
ask_oracleStart or continue independent expert consultations.
oracle_chat_logRecover an Oracle lane after compaction or interruption.

The ceiling is applied during both tools/list and tools/call. Calls are canonicalized and persisted connection policy is hydrated before authorization, so a hidden tool cannot simply be invoked by name and reconnects retain the same profile.

3. Native provider exceptions

ProviderRetained native capabilitiesDeliberately removed
Claude CodeRead for non-text media; WebSearch and WebFetch when enabled.Bash, native text editing/search, tool discovery, delegation, and coding-oriented native tools.
Codexview_image; configured web search when enabled.Shell, patching, third-party MCP, goals, computer use, and multi-agent capabilities.
Routing boundary: RepoPrompt owns local text, search, and edits. Provider-native tools fill the genuine web and binary/media gaps. Claude’s native Read is not technically binary-only, so V1 relies on a clear prompt rule rather than a new extension-aware interception layer.

4. Stable prompt

The Knowledge prompt deliberately excludes dynamic workspace names, model IDs, dates, web availability, and workflow state. This keeps the parent system-prompt prefix stable across turns. It tells the agent to distinguish fact from inference, cite evidence, resist prompt injection in supplied material, write useful conclusions first, and redirect coding/build/Git/shell requests to standard Agent Mode.

Major decisions and turns

Extend RepoPrompt, not build another app

RepoPrompt already owns provider access, Oracle conversations, workspace context, persistence, text editing, and note-friendly workspaces. A separate application would duplicate these foundations and make it harder to carry knowledge directly into coding work.

Knowledge Agent, not only Knowledge Oracle

An earlier design focused on sealing each Oracle participant with packet hashes and participant receipts. The user clarified that the missing product was the lean parent Agent Mode session. The current implementation therefore creates a first-class fresh Knowledge profile.

Remove the verification gate

Packet hashes, prompt hashes, packet_context_clean, model-identity audits, and a DuelRun transport state machine were judged distracting and prompt-heavy for the intended workflow. Ordinary service correctness remains, but the parent model is no longer asked to supervise transport metadata.

Preserve prompt-cache stability

Knowledge is selected only during fresh construction. A standard session is never switched in place. This avoids changing the orchestrator system prompt halfway through a conversation.

Keep the UI secondary

More than half of Oracle usage is still coding-related. The Knowledge entry point therefore lives behind the existing titlebar button’s chevron instead of becoming a prominent mode selector that distracts ordinary coding work.

Use adaptive, optional debate

Years of user experience already established the value of two opinions. The system defaults to direct synthesis, uses one critique for material differences, and reserves a second round for one explicit unresolved issue instead of imposing a pilot gate or fixed debate depth.

Do not fence edits to Markdown

A Markdown-only runtime restriction was rejected because useful knowledge work may target .txt, .org, or existing project documents. Existing workspace/edit validation and prompt guidance remain authoritative.

Restore native media support

The first rewritten plan removed native image/PDF browsing. The user explicitly corrected that decision. V1 now retains Claude media/PDF reading and Codex image viewing while preserving RepoPrompt ownership of text.

What happened to the earlier implementation?

It was not restored or mixed into the current tree. It remains safely preserved as stash@{0}: wip: knowledge harness implementation before plan rethink. The current 41-file implementation was built from the revised profile-oriented plan.

Risks and limits

Risks, limitations, and technical debt

No behavioral quality metric yet

Compiler and contract coverage are strong, but the session did not measure answer quality, tool-use reduction, cache hit rate, cost, or elapsed time across real Knowledge questions.

Claude media routing is prompt-enforced

Claude’s native Read can also read text. V1 tells the model to reserve it for non-text media; there is no extension-aware native-tool guard.

Codex PDF parity is intentionally absent

Codex retains image viewing. Workspace PDF support should not be claimed until a concrete, tested path exists.

Provider rollout is intentionally narrow

OpenCode, Cursor, GLM, Kimi, and other compatible providers remain standard-only until their effective native inventories can be verified.

Full repository suite is not green

The changed feature suites pass, but the broad run currently has ten Git/VCS failures. A PR-ready handoff should preserve that distinction and avoid claiming a globally green baseline.

Three useful test hardening ideas remain

Future coverage could derive production Codex options directly, test full cross-profile placeholder cleanup end-to-end, and exercise a reconnect’s first direct call without a prior tool-list request.

The curated test ledger also retains the known unrelated baseline drift: three missing and two stale WorkspaceProjectedPathSearchTests entries.
