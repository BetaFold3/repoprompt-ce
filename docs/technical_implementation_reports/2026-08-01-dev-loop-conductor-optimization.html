Executive summary

The work attacks two different sources of slowness: unavoidable compilation of a very large SwiftPM test product, and avoidable overhead or failure modes around that build. It does not pretend the root application can always rebuild instantly. Instead, it makes incorrect and hanging runs fail quickly, provides a trustworthy fast path when a valid test artifact already exists, and extracts a narrow group of tests that can avoid the full application graph altogether.

The intended daily loop

1. Edit sourceMake the smallest intended change.
2. Validate sourceRun lint and a focused make dev-test. This performs the incremental build and mints a trusted ticket on success.
3. Iterate instantlyWhile the source and build remain unchanged, use make dev-test-artifact.
4. Prepare contributionRun impacted or broader source-valid checks, then the repository contribution preflight.

What it intentionally does not promise

  • It does not make the first root build after a source edit seconds-class; that run still compiles and links what SwiftPM requires.
  • It does not make an artifact-scoped pass equivalent to a source-valid pass or CI.
  • It does not split the whole application into new modules, increase heavyweight concurrency, or parallelize stateful root tests.
  • It does not guarantee the recorded timing numbers on other machines, toolchains, dependency caches, or workloads.

What was implemented

The six requested tracks landed as one coherent developer-workflow change, followed by the three requested reliability follow-ups.

1. Filter fail-fast and zero-test protection

Observed in code Scripts/conductor.py checks a requested filter against the curated ledger before building. A source-suite fallback supports a genuinely new suite that has not yet been added to the ledger. Invalid filters return exit 64 with close-match suggestions. A filtered run that starts no test case returns exit 66 unless explicitly permitted.

  • RPCE_ALLOW_UNKNOWN_FILTER=1 is the narrow override for a real new suite.
  • RPCE_ALLOW_ZERO_TESTS=1 is the narrow override for intentionally gated execution.
  • The new checks cover root, provider, core, and artifact test operations.

2. Default XCTest hang containment and clearer contention

Observed in code The watchdog now understands XCTest phases rather than treating every period of silence the same. The active-method allowance is max(90s, 4 × ledger runtime + 30s); methods without a runtime use 180 seconds. Startup after the build is bounded at 90 seconds and the gap between methods at 60 seconds. Filtered jobs have a 20-minute outer limit; full-root jobs retain the longer ceiling.

  • Exit 70 identifies a startup, active-method, or between-method deadline.
  • --xctest-stall-seconds overrides only the active-method budget.
  • Run-only artifact tests claim a separate machine-wide xctest slot.
  • Job status exposes waiting-heavy-slot or waiting-xctest-slot and wait telemetry.
  • Termination guards against process-group identifier reuse and re-enumerates descendants after group kill, including escaped child processes.

3. Measurement before architecture surgery

Observed in session A dedicated measurement spike decomposed the warm path and compared swift test --skip-build with direct xcrun xctest. Direct XCTest was faster in isolation (0.06s median), but the agreed adoption rule favored the more portable SwiftPM fast path because its 0.69s median was below the 3-second threshold. The investigation also confirmed one aggregate root test bundle, so merely adding more root test targets would not avoid aggregate linking.

Bonus root cause found during measurement Conductor had injected a unique per-job environment variable into direct Swift children. SwiftPM keys planning caches on the environment, so the unique value forced repeated planning. The implementation now removes that variable for direct Swift invocations while retaining it where child tooling actually needs it.

4. Ticket-bound artifact re-run

Observed in code A successful root dev-test records a build ticket that binds the source snapshot, environment gates, toolchain, test executable, and resource closure. make dev-test-artifact FILTER=… verifies the ticket and bundle before using swift test --skip-build.

  • Dirty tracked and untracked file contents are hashed; symlink identity is preserved.
  • Dirty submodules and unreadable dirty files fail closed, withholding trusted artifact status.
  • The test executable and every regular file in the .xctest/sibling resource-bundle closure contribute SHA-256 content hashes.
  • The bundle is rechecked after slot acquisition and source/artifact state is checked around the run to close mutation races.
  • Missing or changed ticket/artifact state returns exit 65.
  • A changed source tree can still run the prior artifact, but the result is visibly labeled artifact_scope: stale — current source was NOT validated.

5. Owner-side bounded workspace initialization waits

Observed in code WorkspaceManagerViewModel now owns an additive awaitInitialized(timeout:) async throws API. Its waiter registry performs remove-then-resume exactly once on the main actor and supports timeout, cancellation, initialization completion, and workspace-switch completion. The historical indefinite API remains for compatibility.

  • The 52 remaining untimed test call sites were migrated; the current test tree contains 59 bounded calls across 15 files and zero awaitInitialized() calls.
  • Six focused tests cover immediate return, success, timeout diagnostics, cancellation, a 100-iteration success/timeout race, and waiting through a workspace switch.
  • TimedWaits.swift adds bounded polling and semaphore helpers for waits owned by tests.
  • Waiters now resume conservatively after initialization callbacks and any resulting workspace switch, never into a partially switched state.

6. Core-package extraction and tiered policy

Observed in code Packages/RepoPromptCore now owns RepoPromptShared and a reusable RepoPromptMCPCore library. The root repoprompt-mcp product keeps the same product name through a six-line executable entry point. Nine suites and 55 ledgered methods moved to the core target.

  • make dev-core-test and conductor’s core-test operation provide the smaller local lane.
  • CI now has a dedicated core-package job and cache key.
  • Package, layout guardrails, Swift style configuration, and source-layout documentation were updated together.
  • AGENTS.md, development guidance, and validation guidance now distinguish source-valid tests from artifact-only re-runs.
  • dev-test-impacted now fails on unmapped production paths instead of silently degrading; docs-only paths remain exempt.

7. Runtime-aware deadlines and ledger backfill

Observed in code Conductor loads per-method runtime_seconds from the curated ledger at XCTest case boundaries. The current ledger contains 3,285 rows: 3,223 root, 55 core, and 7 provider. Runtime coverage rose from 2,772 of 3,279 rows at HEAD to 3,282 of 3,285 rows in the working tree.

Honest completion note The original 507 missing runtimes were reduced by 504. Three Sentry-gated privacy methods still have blank runtimes. They safely receive the 180-second default budget, but the requested backfill is not literally 100% complete.

Major turns and why they mattered

Start with evidence, not package surgery

The first measurements separated queueing, planning, compilation, linking, and test execution. This prevented the team from attributing a 633-second queued sample to healthy incremental compilation.

Oracle C rejected a test-only timeout race

A task-group race around the old indefinite continuation could itself hang or leak a waiter that retained the full per-window graph. The design moved the deadline into the state owner, where registration, cancellation, and completion can be resolved exactly once.

“Silence watchdog” became phase-aware deadlines

XCTest often emits no output while a legitimate method runs. The final design keys deadlines to case-boundary output and uses ledger runtimes, avoiding a flat 90-second cap for every method.

New root test targets were rejected

SwiftPM produces one aggregate root .xctest bundle on this toolchain. Splitting files into additional root targets would still link the whole aggregate. A separate local package is the mechanism that actually reduces the graph.

Artifact speed was separated from source validity

The team rejected a repo-wide “probably fresh” hash cache as an unbounded input inventory. The final interface is explicit: ordinary dev-test builds and validates source; dev-test-artifact re-runs a recorded artifact and labels its scope.

Oracle review changed provenance from metadata to content

Reviewers found false-green paths involving untracked edits, a ticket not bound to the exact bundle, same-size resource replacement with preserved timestamps, dirty submodules, and unreadable files. Multiple review rounds added content hashes, fail-closed behavior, post-slot verification, and regression tests.

Scheduler changes stayed deliberately small

Build-lane ownership remains in place so a concurrent build cannot relink a bundle while XCTest is using it. The lower-risk improvement is a separate machine-wide XCTest slot, not a broad admission-order rewrite or more heavyweight concurrency.

Accepted overhead

Strong provenance hashes the artifact closure multiple times. Oracle A noted caching as an optional optimization if the ~4.8s live path becomes material.

Compiler experiment deferred
PCH unchanged

-disable-bridging-pch remains. History contains no rationale, but an A/B result was not strong enough to change it safely.

  • Artifact tests are point-in-time attestations. A later external edit does not retroactively invalidate a completed job, but it does require a new source-valid run before further contribution evidence.
  • Build tickets depend on Git readability. Dirty submodules, unreadable files, or an unreadable artifact deliberately cause a fail-closed result.
  • Core extraction adds a nested package boundary. It has its own manifest and lockfile, CI cache key, and ownership rules; dependency updates must keep root and core needs deliberate.
  • The indefinite API still exists. This preserves compatibility. Production callers can still choose indefinite semantics; the completed migration targeted test call sites.
  • One reviewer nit remains optional. Oracle A noted that conductor test --list may also mint a ticket and that closure verification is repeated. Neither was considered a correctness blocker.
  • No database, migration, signing, release-channel, bundle-ID, or external API change was observed. The root repoprompt-mcp product name and CLI version contract remain intact.
