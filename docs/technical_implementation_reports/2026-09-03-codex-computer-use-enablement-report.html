Codex computer-use enablement

Technical implementation, troubleshooting, and live-test report for the work in rp/agent/2802da8c-agent.

Report date: 2026-09-03Live smoke test passedmacOS authorization fix included

Outcome

The change adds a saved, default-off gate for Codex computer use.

A gate is a switch that must be on before a feature can run.

The user turns the gate on through RepoPrompt CE's app_settings tool.

The user then starts one computer-use turn with /computer-use in a normal Codex Agent Mode session.

The change does not add a visible Settings-screen toggle.

The change does not install a computer-use server.

The change does not grant macOS permissions.

The implementation now declares why RepoPrompt sends Apple Events. An Apple Event is a macOS message that one application sends to another for automation.

A live read-only computer-use test passed after the server path and macOS authorization issues were corrected.

Expected safety rule. Safe Managed sessions and Knowledge sessions cannot enable computer use. Safe Managed means a session started through MCP with restricted defaults. MCP is the protocol that lets an agent call tools supplied by another process.

Why this changed

Observed in the session. Computer use already had a slash workflow and runtime support. RepoPrompt kept the feature disabled with a fixed value.

The requested plan made the feature opt-in.

The plan also required one saved source of truth.

The implementation uses the global settings document for that source.

The environment variable RP_CODEX_COMPUTER_USE can still force the gate on.

Injected UserDefaults remain available for isolated tests only.

What to expect

  • The setting starts off for users who have no saved value.
  • /computer-use shows a direct disabled message while the setting is off.
  • Turning the setting on makes the slash workflow eligible in a normal Codex session.
  • The slash command enables computer use for that explicit turn. It does not enable every Codex turn.
  • The current turn must be idle, or waiting for the user.
  • The command cannot be combined with attachments, tagged files, or another selected workflow.
  • A configured MCP server named computer-use is still needed for actual computer-use tools.
  • Codex should report missing tools instead of inventing tool calls.
  • macOS may ask RepoPrompt for Automation access to ChatGPT Computer Use and System Events.
  • macOS may also ask the computer-use helper for Accessibility or Screen Recording access. Debug and release identities can need separate grants.
  • Full-auto mode may accept requests from the computer-use server for that explicit turn. Other permission policies still show approval prompts.

Run these commands from the root of the repository checkout or implementation worktree.

2. Build and launch the worktree app

This step changes the visible app. Close or preserve work in any running debug app first.

make dev-run

The coordinated build writes the debug app to .build/debug/RepoPrompt.app.

3. Check the CE debug CLI

make debug-cli-status

If the debug CLI is missing or stale, install the one built from this checkout.

make install-debug-cli

Use rpce-cli-debug. Do not use the production rp-cli.

4. Find the target window

rpce-cli-debug -e 'windows'

Choose the positive window ID for the debug app. Replace <window-id> below.

5. Confirm that the new setting exists and starts off

rpce-cli-debug -w <window-id> -c app_settings -j '{"op":"get","key":"agent_mode.codex_computer_use_enabled"}'

Expect a boolean value. A new profile should return false.

6. Confirm the disabled user path

  1. Open a standard Agent Mode tab in the debug app.
  2. Select Codex.
  3. Enter /computer-use inspect the frontmost app without changing anything.
  4. Send the turn.

Expect the message that Codex computer use is turned off. The message should name the settings key.

7. Turn on the gate

rpce-cli-debug -w <window-id> -c app_settings -j '{"op":"set","key":"agent_mode.codex_computer_use_enabled","value":true}'

Expect status to be ok. Expect new_value to be true.

8. Check the eligible workflow

  1. Use a normal Codex Agent Mode session.
  2. Make sure no other workflow is selected.
  3. Do not attach images or files.
  4. Enter /computer-use inspect the frontmost app and report what you see; do not click or type.
  5. Send the turn.

Expect a user bubble marked /computer-use.

If a computer-use MCP server is configured, expect Codex to discover or call its tools.

If no such server is configured, expect Codex to say that no computer-use tools are available.

9. Check macOS permission handling

Only do this with a non-destructive inspection request.

Open System Settings → Privacy & Security → Automation.

Allow the RepoPrompt debug app to control ChatGPT Computer Use and System Events.

Use Privacy & Security → Screen Recording to let ChatGPT Computer Use inspect visible pixels.

Grant Accessibility only when you want it to click, type, or otherwise control the interface.

If the Automation prompts are stale, quit RepoPrompt and reset the debug identity before relaunching:

tccutil reset AppleEvents com.pvncher.repoprompt.ce.debug

This resets every Automation decision for the debug app. It does not reset Accessibility or Screen Recording.

10. Turn the gate off again

rpce-cli-debug -w <window-id> -c app_settings -j '{"op":"set","key":"agent_mode.codex_computer_use_enabled","value":false}'

Repeat step 6. Expect the disabled message again.

Live troubleshooting record

  1. The gate worked. The app_settings call changed agent_mode.codex_computer_use_enabled from false to true. The Agent Mode bubble showed the computer icon and /computer-use label. This proved that RepoPrompt parsed the workflow.
  2. The first run had no tool. Codex said no computer-use tool was available. The active Codex profiles used a relative MCP command such as ./Codex Computer Use.app/... with cwd = ".". RepoPrompt starts Codex from the selected workspace. The relative path therefore pointed to the wrong location.
  3. The MCP paths were repaired locally. On the test machine, the affected ~/.codex/config.toml and profile-specific files under ~/.codex-auth-switcher/app-server/workers/ now use the absolute helper path under ~/.codex/computer-use/. These user-level configuration edits are not repository changes. The saved server remains disabled. The explicit workflow enables it for one turn.
  4. The second run reached macOS. The helper reported error -1743. This code means an Apple Event was not authorized. Enabling RepoPrompt → System Events removed that direct denial.
  5. The next runs timed out. Three tool calls each waited about two minutes and returned -1712, or errAETimeout. The delay made the receiver look hung.
  6. The macOS log showed the hidden denial. SkyComputerUseClient sent an Apple Event to SkyComputerUseService. TCC, the macOS privacy service, attributed the request to com.pvncher.repoprompt.ce.debug. It denied RepoPrompt access to com.openai.sky.CUAService. The client then surfaced only a timeout.
  7. The app bundle lacked the required declaration. Both the coordinated debug bundle and /Applications/RepoPrompt CE Dev.app lacked NSAppleEventsUsageDescription. The repository template now contains it. Both hardened-runtime entitlement templates now allow Apple Events automation. The entitlement addition came after the validated debug rebuild and still needs verification in a hardened-runtime artifact.
  8. The rebuilt app succeeded. The debug app was rebuilt. Its Automation decisions were reset. The user allowed the new prompts. The same read-only /computer-use test then worked.

Identity detail. The coordinated debug app and RepoPrompt CE Dev.app use bundle ID com.pvncher.repoprompt.ce.debug with the same development signing identity. The release app uses com.pvncher.repoprompt.ce and a different signing identity. macOS permissions follow those identities, not only the visible application name.

Major decisions and turns

  1. Use one production authority. The implementation moved the production gate to GlobalSettingsStore. This avoids two saved values that could disagree.
  2. Keep compatibility narrow. The old UserDefaults key remains only for injected test stores. The environment variable remains a force-on switch. The code does not migrate a stale user value into the new global setting.
  3. Keep the default off. Computer control has security and privacy effects. Users must opt in.
  4. Require an explicit slash turn. Enabling the setting does not activate tools on ordinary turns. The user must type /computer-use.
  5. Add the tool API before UI polish. The plan asked for the app_settings key. It did not ask for a visible Settings toggle. The shared binding supports a future toggle, but the current view does not render it.
  6. Expand safety after review. OracleB found that Safe Managed could still reach activation paths. The implementation added checks at slash validation, pending activation, desired controller state, and controller construction.
  7. Correct a test integration error. The first test build found a factory closure with the wrong arity. The closure was updated to match the live signature.
  8. Stop the review loop when high-priority findings closed. OracleA closed its source-of-truth and comment findings. OracleB closed its Safe Managed P1 after fresh re-reviews.
  9. Use runtime evidence when the visible error was misleading. Repeated -1712 errors looked like a hung receiver. Unified macOS logs showed a hidden TCC denial instead.
  10. Fix the app declaration, not only local permissions. Manual toggles could not supply the missing Apple Events purpose string. Adding it to the committed template fixes every newly packaged app.
