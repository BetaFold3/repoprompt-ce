Cursor parameter catalog: Phase B

Phase B keeps Cursor model parameter choices available when a temporary refresh fails. It saves the last valid choices, tells the user what happened, and tries again with a controlled delay.

Executive summary

The model parameter menu now keeps a safe saved copy.

Cursor publishes basic model names and parameter choices through different ACP calls. Before this work, a temporary error could leave the model names visible but remove the parameter choices for the rest of the app session. Phase B stores a valid set of choices locally and uses it until Cursor supplies a newer valid set. Session and plan

What changes for users: A temporary Cursor login, network, timeout, or malformed-response problem should not make an already known parameter menu disappear. The Cursor settings card shows a short status message instead.

Before Phase B

  • Parameter choices lived only in memory.
  • A failed refresh could remove all parameter submenus.
  • The failure had no clear settings message.
  • The next app launch had no saved parameter choices.

After Phase B

  • A valid nonempty parameter list is saved in its own versioned store.
  • Bad or temporary results keep the last valid list.
  • Settings show the saved-copy state and the safe failure reason.
  • The app loads the saved list before it starts background refresh.

Implementation details and expected result

How the implementation behaves

In this report, a parameter catalog is the saved list of per-model choices, such as context, reasoning, and fast mode. It is separate from the basic model list. Observed in code

Phase B behavior for the Cursor parameter catalog
Situation What the app does What a user can see
Cursor returns a valid nonempty list Replace the old list and save it with a time stamp. Parameter choices are current. Settings say that they are up to date.
App starts after a previous valid result Load the saved list first. Refresh in the background. Choices can remain available while the refresh is pending, when the feature is enabled.
Authentication, discovery, timeout, extension, or malformed-response failure Keep both the basic model list and the last valid parameter list. Record a safe failure type. Retry later. The existing choices remain. Settings say that a saved copy is in use and give a short reason.
Cursor says the extension method does not exist Clear the parameter list. This is an authoritative signal that the Cursor version does not support it. Settings say: “This Cursor version doesn't expose model parameters.”
Cursor returns a valid empty model list Clear the parameter list. This is an authoritative result. Settings say that Cursor currently exposes no parameterized models.
Saved data is corrupt or has a newer unknown version Do not use it and do not delete it. A later valid nonempty result may replace it. No unsupported data is shown. There is no migration prompt.
Refresh stops because the app is shutting down Stop cleanly. Do not turn shutdown into a failure. No false “last refresh failed” status from normal shutdown.

Key implementation files and their responsibilities
  • CursorModelParameterStore owns the CursorModelParameterCatalogV1 data format. It writes only valid, nonempty lists. It keeps corrupt or unknown-version bytes until a future valid nonempty write replaces them.
  • CursorModelParameterCatalog owns the in-memory list, its status, and the all-or-nothing parser. It sends a data notification only when the list changes. It sends a separate status notification for state changes.
  • CursorACPModelPollingService owns polling. It keeps normal model discovery useful even when only parameter enrichment fails.
  • CLIProvidersSettingsView shows the status text. It does not put status rows inside model pickers.

Major decisions and reasoning

Why the work takes this shape

Use a separate versioned store

The parameter list uses CursorModelParameterCatalogV1. It does not change the existing basic-model store. This limits migration risk and lets old builds ignore the new key.

Result: base models and parameter choices can change independently.

Reject a bad reply as one whole unit

If one model entry or one select choice is structurally invalid, the catalog does not use any part of that reply. It keeps the prior valid list.

Reason: a partial list could remove valid choices without proof that Cursor removed them.

Clear only on authoritative signals

The app clears the saved list only when Cursor says the method does not exist or when Cursor sends a valid empty list.

Reason: these signals say that the old list is no longer valid.

Show status in Settings, not in a picker

The design uses one settings row. A separate status notification does not force menu rebuilding when only the message changes.

Reason: this gives an explanation without adding noise to every picker.

Keep retry controlled and safe

Failure logs use fixed, safe phrases. The first retry delay is about 15 seconds. Repeated failures increase the delay to a 300-second limit. A success resets it.

Result: the app can recover after re-authentication without an app restart.

Keep Phase C separate

The work does not add Cursor parameter metadata to agent_manage list_agents. The plan keeps that as Phase C.

Reason: the metadata is dependable only after this persistence work is in place.

1. Define the failure boundary

The phase plan records the key incident: basic Cursor models remained visible after a refresh error, but the in-memory parameter choices disappeared. The implementation treats a valid saved parameter list as separate data that needs its own lifecycle. Plan evidence

2. Make the parser all-or-nothing

The chosen rule is retain-last-good. A malformed reply records a failure but does not replace memory or saved data. Observed in code

3. Add an understandable status surface

The status moves to the Cursor settings card. It can say that data is live, saved, refreshing, unavailable, unsupported, or disabled. Observed in code

  • Keep corrupt or newer storage records without changing their unknown parts.

  • Remove an unnecessary overload.

Maintainer notes
